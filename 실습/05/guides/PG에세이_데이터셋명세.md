# 데이터셋 명세서: Paul Graham 에세이 모음

실습 5-3(Paul Graham 에세이를 pgvector에 적재하고 질문하기)에서 쓰는 데이터셋이다.

## 1. 개요

| 항목 | 내용 |
|---|---|
| 이름 | Paul Graham Essay Collection (`sgoel9/paul_graham_essays`) |
| 내용 | Paul Graham이 개인 웹사이트에 쓴 에세이 215편 |
| 주제 | 스타트업, 창업, 투자, 프로그래밍, 글쓰기, 교육 |
| 언어·형식 | 영어, CSV 파일 1개(약 2.9MB) |
| 용도 | RAG 적재와 질의응답 실습 |

## 2. 출처와 버전

| 항목 | 내용 |
|---|---|
| 데이터셋 | huggingface.co/datasets/sgoel9/paul_graham_essays |
| 원문 출처 | Paul Graham 웹사이트(paulgraham.com) |
| 등록·수정 | 2024년 4월, Hugging Face 사용자 `sgoel9` |
| 고정한 커밋 | `0c7155a53c25e24c9b9858314460e0ee1f5c3e4e` |
| 파일 이름 | `pual_graham_essays.csv` |

- 파일 이름의 `pual`은 원본의 오타다. 주소를 고치지 않는다.
- 커밋으로 고정했으므로 데이터셋이 바뀌어도 실습 결과는 같다.
- 내려받는 데 로그인이나 토큰이 필요 없다.

## 3. 이용 조건

- 데이터셋 페이지에는 MIT 라이선스로 표시되어 있고, Paul Graham과 그의 웹사이트를 출처로 밝히라고 적혀 있다.
- 에세이 본문의 저작권은 Paul Graham에게 있다. 올린 사람이 본문의 이용 조건까지 정할 수 있는지는 확인되지 않는다.
- 그래서 수업 안에서 실습용으로만 쓰고, 본문을 다시 배포하거나 길게 옮기지 않는다.

## 4. 구조

한 행이 에세이 한 편이다. 행은 날짜순이 아니다.

| 열 | 자료형 | 설명 | 예 | 실습에서 |
|---|---|---|---|---|
| `id` | 정수 | 에세이 번호 | `0` | 메타데이터 `essay_id` |
| `title` | 문자열 | 제목 | `The Age of the Essay` | 메타데이터 `title` |
| `date` | 문자열 | 발표 시기 | `September 2004` | 메타데이터 `date` |
| `text` | 문자열 | 본문 전체 | (6절) | 분할·임베딩 |

## 5. 기초 통계

| 항목 | 값 |
|---|---|
| 에세이 수 | 215편 |
| 발표 시기 | 1993년 9월 ~ 2023년 1월 (2009년이 24편으로 가장 많다) |
| 본문 글자 수 | 최소 404, 중앙값 8,601, 평균 13,668, 최대 75,483 |
| 전체 분량 | 약 294만 글자, 약 51만 단어 |
| 청크 수 | 앞 30편 444개(실행 확인), 전체 약 3,800개(추정) |

- 청크 수는 실습 설정(1000자, 겹침 150자) 기준이다. 전체 청크 수는 앞 30편의 비율로 추정했다.
- 글 길이 차이가 크다. 짧은 글은 청크 하나, 가장 긴 글(What I Worked On)은 청크 수십 개가 된다.

## 6. 본문의 형식

본문은 순수한 텍스트가 아니라 Markdown에 가깝다.

| 형식 | 예 | 들어 있는 편수와 영향 |
|---|---|---|
| 굵은 소제목 | `**Appendix: ...**` | 177편. 문단 경계가 되어 분할에 도움이 된다 |
| 링크 | `[essay](gh.html)` | 199편. 상대 주소라서 링크로 쓸 수 없다 |
| 각주 | 끝의 `Notes` 절 | 133편. 각주도 청크가 된다 |
| 문단 구분 | 빈 줄 | 문단 단위로 나누기 좋다 |

## 7. 적재 테이블 구조

적재 워크플로우가 만드는 `pg_essays` 테이블이다. 한 행이 청크 하나다. 테이블은 `Postgres PGVector Store` 노드가 처음 실행될 때 만든다.

| 컬럼 | 자료형 | 설명 |
|---|---|---|
| `id` | uuid | 청크 번호. 기본 키이며 저장할 때 자동으로 만든다(`gen_random_uuid()`) |
| `text` | text | 청크의 본문. 에세이 본문을 1000자 안팎으로 나눈 조각이다 |
| `metadata` | jsonb | 청크의 부가 정보. 아래 표 |
| `embedding` | vector | `text`의 임베딩. `text-embedding-3-large`로 만든 3072차원 벡터다 |

`metadata`에 들어가는 값은 다음과 같다.

| 키 | 넣는 곳 | 예 |
|---|---|---|
| `essay_id`, `title`, `date` | Data Loader의 Metadata 설정(CSV의 `id`, `title`, `date`) | `"0"`, `"The Age of the Essay"`, `"September 2004"` |
| `loc.lines` | Data Loader가 자동으로 붙임. 원문에서 청크가 있는 줄 범위 | `{"from": 1, "to": 7}` |
| `source`, `blobType` | Data Loader가 자동으로 붙임 | `"blob"`, `"text/plain"` |

- `embedding`은 차원 제한 없이 `vector`로 만들어진다. 다른 임베딩 모델로 적재해도 막지 않으므로, 적재와 검색의 모델을 같게 둔다.
- 한 에세이의 청크는 `metadata->>'essay_id'`가 같다. 에세이 단위로 세거나 지울 때 이 값을 쓴다.

## 8. 품질 문제

중복된 제목이나 본문은 없다. 그 밖의 문제는 다음과 같다.

| 문제 | 내용 | 처리 |
|---|---|---|
| 날짜 없음 | 3편(What Languages Fix 등) | 그대로 둔다. 출처의 날짜가 빈다 |
| 빠진 번호 | `id` 0~217 중 115, 138, 195가 없다 | 연속 번호로 가정하지 않는다 |
| 깨진 문자 | 23편에 `�` 75개. 원래 대시(—) 자리로 보인다 | 그대로 둔다 |
| 날짜 형식 | 날짜형이 아닌 `월 연도` 문자열 | 기간으로 거르려면 변환한다 |

## 9. 실습에서 쓰는 방법

1. `HTTP Request`로 CSV를 파일로 내려받는다.
2. `Extract from File`(CSV)로 한 편을 아이템 하나로 바꾼다. 본문에 쉼표와 줄바꿈이 있으므로 CSV 파서를 쓴다.
3. `Limit`으로 앞 30편만 남긴다. 비용과 시간을 줄이기 위해서다.
4. `text`만 분할·임베딩하고, `id`, `title`, `date`는 메타데이터로 붙인다.
