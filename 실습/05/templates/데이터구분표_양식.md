# 데이터 구분표 양식

> 실행이 끝난 뒤에도 남는 값을 네 가지 데이터와 외부 조회로 나누는 양식이다. 5장 실습 5-4의 1단계에서 쓴다.
> 파일 이름은 `05_데이터구분표.md`로 한다. 이론 5.1절을 참고한다.

## 1. 구분 기준

| 구분 | 담는 것 | 찾는 키 | 수명 | 쓰는 주체 |
|---|---|---|---|---|
| **실행 안의 데이터** | 이번 실행에서 노드 사이에 흐르는 값 | 아이템 | 실행이 끝나면 없어진다 | 노드 |
| **대화 메모리** | 한 대화에서 오간 메시지 | 세션 ID | 대화가 이어지는 동안(보관 기한까지) | 에이전트 노드 |
| **업무 상태** | 처리 건의 현재 상태와 근거 | 문의·요청 식별자, 세션 ID | 업무가 끝날 때까지와 보관 기간 | 워크플로우의 규칙 |
| **지식 베이스** | 규정·안내 문서의 청크 | 검색어의 뜻, 문서 번호 | 문서가 바뀔 때까지 | 적재 워크플로우 |
| **외부 조회** | 다른 시스템이 관리하는 사실 | 주문번호 등 | 저장하지 않고 필요할 때 조회한다 | 조회 도구 |

| 번호 | 값 | 구분 | 저장하는 곳(테이블 이름 또는 "저장하지 않음") | 그렇게 나눈 이유 |
|---|---|---|---|---|

## 3. 스스로 확인할 질문

- 두 곳에 함께 남는 값이 있는가? 있다면 두 곳에 남기는 목적이 각각 무엇인가?
- 대화 메모리에만 남는 값 중에 규칙이 읽고 판단해야 하는 값이 있는가? 있다면 업무 상태로 옮겨야 하지 않는가?
- 저장하지 않기로 한 값을 나중에 다시 알아야 하면 어디에서 다시 가져오는가?
