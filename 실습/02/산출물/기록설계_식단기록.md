## 데이터 계약

### 음식사진 분석 LLM 분석 출력 데이터

| 필드 | 데이터 타입 | 필수 | 형식·허용 값 | 없거나 틀릴 때 |
|---|---|---|---|---|
| `is_food` | boolean | 필수 | `true`, `false` | 다시 한번 분석을 한다. 재 분석결과도 값이 없으면 사용자에게 알린다. |
| `meal_type`  | string, null | `is_food`가 `true`이면 필수 | `breakfast`, `lunch`, `dinner`, `snack` 중 하나 |  전송된 시간을 보고 추정한다. (05:00 ~ 10:59 : `breakfase`, ....)  |
| `foods` | Array  | `is_food`가 `true` 이면 필수 | 음식 하나당 `object`. `object` 구성 필드는 아래를 참조  | 빈배열이면 음식을 제대로 파악못한 것을 처리하고 사용자에게 알린다.  |
| `foods[].food_name` |  string | 필수 | 없음 | 기록하지 않고 사용자에게 알린다. |
| `foods[].amount` | string, `null` | 필수아님 | 없음. ("10개", "1컵", "200ml") | `null` 로 처리 |
| `foods[].calories` | number, `null` | 필수아님 | 0이상 양수만가능 | `null`처리 |
| `foods[].protein_g` | number, `null` | 필수아님 | 0이상 양수만가능 | `null`처리 
| `foods[].sodium_mg` | number, `null` | 필수아님 | 0이상 양수만가능 | `null`처리   |
| `foods[].confidence` | string | 필수 | `high`, `medium`, `low` 중 하나 |  `low` 로 처리 |
| `summary` | string | 필수아님 | 없음 | 기록표에는 저장하지 않는다. 없으면 빈문자 처리한다. |



### 두 워크플로우가 공유하는 신단 기록행 계약

| 필드 | 데이터 타입 | 형식·허용 값 | 쓰는 쪽(기록)의 규칙 | 읽는 쪽(리포트)의 해석 |
|---|---|---|---|---|
| `record_id` | string  | `R-` 다음에 숫자 세개로 구성 ("R-010") | 중복되지 않는 값 | 행/값 식별자 |
| `recorded_at` | string | ISO 8601, 한국시간 (`+09:00`) |  사진 받은 일시  | 보고 작성 날짜의 식단을 찾을 때 사용  |
| `date` | string | 날짜 (`YYYY-MM-DD`)  | `recorded_at`에서 날짜만 추출 | 당일 날짜를 확인할 때 사용 |
| `meal_type` | string | `breakfast`, `lunch`, `dinner`, `snack` 중 하나  | LLM의 분석결과값  | 끼니를 이용한 다양한 집계  |
| `food_name` | string | 없음 | LLM 분석결과값 | 음식이름 표기 |
| `amount` | string | 없음 |  LLM 분석결과값   | 표기 |
| `calories` | number, 빈칸 | 0이상 양수  | LLM 분석결과값  | 그 음식의 성분양. 각종 리포트 집계시 사용. |
| `protein_g` | number, 빈칸 | 0이상 양수 |  LLM 분석결과값 |  그 음식의 성분양. 각종 리포트 집계시 사용.|
| `sodium_mg` | number, 빈칸 | 0이상 양수 |  LLM 분석결과값 |  그 음식의 성분양. 각종 리포트 집계시 사용.|
| `confidence` | string | `low`, `medium`, `high` | LLM 분석결과값 | 집계리포트에서 집계시 값 포함여부를 결정하는데 사용. |
| `message_id` | string | 메신저에서 제공하는 형식 그대로 사용. | 메신저 제공값 | 사용자가 원본 내용을 찾을 때 사용. |
