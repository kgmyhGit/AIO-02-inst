# 업무 분해도: 하루마켓 배송·반품 문의 처리

> 실습 1-3의 예시 답안

- 작성자: 예시 답안
- 작성일: 202X-XX-XX
- 대상 업무 범위: 웹 문의 게시판으로 접수된 배송·반품 문의를 받아, 문의마다 자동 안내, CS 담당자 승인 후 안내, CS 담당자 처리 중 하나로 넘겨진 상태에서 끝난다.
- 사용한 자료: `배송반품_문의.csv`(INQ-001~INQ-008), `주문목록.csv`(O-1001~O-1008), `쇼핑몰_정책요약.md`(공통 기준, 배송, 반품)

## 요청 유형 목록

| 유형 값 | 뜻 |
|---|---|
| `shipping_status` | 배송 일정·위치 문의 |
| `return_change_of_mind` | 단순 변심 반품 |
| `return_defect` | 불량·오배송·구성품 누락·상품 정보와 다름에 따른 반품 |
| `mixed` | 여러 요청이 섞여 있음 |
| `other` | 위에 해당하지 않음 |


## 1. 단계별 판단 주체

| 단계 | 하는 일 | 입력 | 결과 | 판단 주체 | 선택 이유 | 사람에게 넘기는 조건 |
|---|---|---|---|---|---|---|
| 접수 | 웹 문의를 받아 고객 이름, 주문번호, 문의 내용이 있는지와 주문번호 형식을 확인한다 | 웹 문의 입력 | 문의 기록, 누락 항목 | 규칙 | 필수 항목과 형식이 정해져 있다 | 없음. 주문번호가 없으면 자동으로 주문번호를 요청한다 |
| 분류 | 요청 유형을 다섯 가지 중 하나로 정하고, 사유 불명확·분쟁 언급·재문의 언급 여부를 표시한다 | 문의 내용 | 유형 값, 표시 3개 | LLM + 규칙 검사 | 고객 문장은 표현이 다양해 규칙으로 잡기 어렵다. 결과가 유형 목록 안에 있는지 규칙으로 검사한다 | 유형이 `mixed`·`other`이거나, 목록 밖 값이거나, 사유 불명확·분쟁·재문의 표시가 있으면 넘긴다 |
| 조회 | 주문번호로 주문 상태, 출고일, 수령일, 결제 금액과 고객 이름을 가져온다 | 주문번호 | 주문 정보 | 규칙 | 주문번호로 한 번 조회하면 되고 순서가 고정되어 있다 | 주문이 없거나 고객 이름이 일치하지 않으면 안내 없이 넘긴다 |
| 판단(배송) | 출고 후 경과 영업일을 계산해 도착 예상 안내와 지연 조사 중 처리안을 정한다 | 유형, 주문 정보, 정책 | 처리안 | 규칙 | 정책에 배송 기간 조건이 명확하다 | 배송 지연 조사 대상이면 넘긴다 |
| 판단(반품) | 반품 경과일, 배송비 부담, 환불 예정 금액을 계산해 처리안을 만든다 | 유형, 주문 정보, 정책 | 처리안 | 규칙 | 정책에 기한과 금액 조건이 명확하다 | 정책에 기준이 없는 경우(세트 일부 불량)면 넘긴다 |
| 승인(배송) | 없음 | 없음 | 없음 | 없음 | 배송 안내에는 환불이나 데이터 변경이 없어 확정할 결정이 없다 | 없음 |
| 승인(반품) | 환불이 포함된 처리안을 확정한다. 불량 반품은 사진 등으로 사실을 확인한 뒤 확정한다 | 처리안, 주문 정보, 적용 정책 조항, 사진(불량 반품) | 승인 또는 거절 | 사람(CS 담당자) | 환불은 되돌리기 어렵고 정책상 담당자 승인이 필요하다. 불량 사실은 규칙으로 확인할 수 없다 | 환불이 포함된 모든 처리안 |
| 응답(주문번호 요청) | 접수에서 주문번호가 없으면 안내문 틀로 주문번호를 요청한다 | 누락 항목 | 고객 안내 | 규칙 | 안내 내용이 정해져 있다 | 없음 |
| 응답(배송) | 도착 예상 안내나 조사 중 1차 안내를 안내문 틀로 보낸다 | 처리안 | 고객 안내 | 규칙 | 안내 내용이 정해져 있다 | 지연 조사 결과의 안내는 담당자가 응답한다 |
| 응답(반품) | 불가 안내는 안내문 틀로 보내고, 반품 안내는 처리안 기반 초안을 승인 때 함께 확인한 뒤 보낸다 | 확정된 처리안 | 고객 안내 | 규칙(불가 안내), LLM 초안 → 사람 확정(반품 안내) | 불가 사유는 정책 조항별로 정해져 있고, 반품 안내는 개별 사정을 반영해야 한다 | 사람에게 넘어간 문의는 담당자가 응답을 작성하거나 초안을 고친다 |

## 2. 요청별 처리 경로

접수일은 2026-09-10(목)이다. 배송 경과는 출고일 다음 영업일부터, 반품 경과일은 수령일 다음 날부터 달력 날짜로 센다.

| 요청 ID | 요청 유형 | 확인한 사실 | 자동으로 끝나는 범위 | 사람이 개입하는 단계와 이유 |
|---|---|---|---|---|
| INQ-001 | `shipping_status` | 출고 09-02, 아직 `shipped`. 출고 후 6영업일이 지나 지연 조사 대상이다 | 접수, 분류, 조회, 지연 기준 판단, 조사 중 1차 안내 | 판단 이후: 담당자가 택배사에 확인한다 |
| INQ-002 | `shipping_status` | 출고 09-09, `shipped`. 도착 예상 09-10~09-14 | 전부 | 없음 |
| INQ-003 | (접수 단계에서 멈춤) | 주문번호가 없다. 같은 이름의 주문이 있지만 본인 주문인지 확인되지 않았다 | 접수에서 주문번호 누락을 확인하고 주문번호 요청 안내 발송 | 없음 |
| INQ-004 | `return_change_of_mind` | 수령 후 3일, 미착용·택 있음(고객 진술). 결제 39,000원에서 배송비 6,000원을 빼 환불 예정 33,000원 | 접수, 분류, 조회, 판단, 안내 초안 | 승인: 환불이 포함된다 |
| INQ-005 | `return_defect` | 수령 후 2일, 세트 2개 중 1개 파손(고객 진술). 세트 일부 불량의 기준이 없다 | 접수, 분류, 조회 | 판단: 사진 확인과 처리 기준 결정. 승인: 환불이 포함된다 |
| INQ-006 | `return_change_of_mind` 또는 `return_defect`, 사유 불명확 표시 | 수령 후 16일, 착용함. '색이 사진과 다르다'고 주장한다 | 접수, 분류 | 분류 이후 전부: 단순 변심인지 상품 정보 차이인지 사진과 상품 페이지로 결정 |
| INQ-007 | `mixed` | 수령 후 4일, 2종 중 1종 누락, 받은 상품도 반품 원함 | 접수, 분류 | 분류 이후 전부: 누락 조사와 배송비 부담 판단 |
| INQ-008 | `return_defect`, 분쟁·재문의 표시 | 수령 후 9일, 신고 언급, 세 번째 문의라고 주장 | 접수, 분류 | 분류 이후 전부: 분쟁 언급으로 즉시 넘긴다 |


## 3. 아직 정해지지 않은 사항

- 세트 상품의 일부만 불량인 경우의 처리 기준이 없다(INQ-005).
- 재문의 여부를 확인할 문의 이력 데이터가 없다. INQ-008의 '세 번째 문의'는 고객의 말로만 확인된다.
