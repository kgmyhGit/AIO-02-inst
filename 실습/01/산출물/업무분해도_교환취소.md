# 업무 분해도: 하루마켓 교환·주문 취소 문의 처리

- 작성자: 예시 답안
- 작성일: 202X-XX-XX
- 대상 업무 범위: 교환·주문 취소 문의 메일이 접수되면 시작한다. 고객에게 자동 안내를 보냈거나, 담당자가 승인한 처리를 마치고 결과를 안내했거나, 문의를 담당자에게 넘겼으면 끝난다.
- 사용한 자료: `교환취소_문의.csv`(INQ-101~INQ-108), `주문목록.csv`(O-2001~O-2010), `재고목록.csv`, `쇼핑몰_정책요약.md`(공통 기준, 교환, 주문 취소)

## 요청 유형 목록

| 유형 값 | 뜻 |
|---|---|
| `exchange_option` | 같은 상품의 다른 옵션(사이즈·색상)으로 교환 |
| `exchange_other_product` | 다른 상품으로 교환 |
| `cancel_full` | 주문 전체 취소 |
| `cancel_partial` | 일부 수량 취소 |
| `mixed` | 여러 요청이 섞여 있음 |
| `other` | 위에 해당하지 않음 |


## 1. 단계별 판단 주체

| 단계 | 하는 일 | 입력 | 결과 | 판단 주체 | 선택 이유 | 사람에게 넘기는 조건 |
|---|---|---|---|---|---|---|
| 접수 | 메일에서 고객 이름, 주문번호, 문의 내용을 확인한다 | 문의 메일 | 문의 기록, 누락 항목 | 규칙 + LLM | 메일 본문은 형식이 정해지지 않은 자연어 문장이라 본문에서 주문번호를 LLM으로 추출하고, 주문번호 형식은 규칙으로 검사한다 | 없음. 주문번호가 없으면 자동으로 주문번호를 요청한다 |
| 분류 | 요청 유형과 교환 사유를 분류하고 원하는 옵션·취소 수량을 추출하며 분쟁·재문의 여부를 표시한다 | 문의 내용 | 유형 값, 교환 사유, 요청 옵션, 취소 수량, 표시 | LLM + 규칙 검사 | 표현이 다양하다. 유형이 목록 안에 있는지, 수량이 숫자인지 규칙으로 검사한다 | 유형이 `mixed`·`other`이거나 목록 밖 값, 분쟁·재문의 표시가 있으면 넘긴다 |
| 조회 1 | 주문 정보를 가져온다 | 주문번호 | 주문 정보 | 규칙 | 교환과 취소 모두 주문번호로 한 번 조회하면 되고 순서가 고정되어 있다 | 주문이 없거나 이름이 일치하지 않으면 넘긴다 |
| 조회 2(교환) | `exchange_option`이면 교환할 옵션의 재고를 가져온다 | 요청 옵션 | 재고 | 규칙 | 상품과 옵션으로 재고 목록에서 찾으면 된다 | 없음. 재고가 0이면 판단(교환)에서 불가 안내를 정한다 |
| 판단(교환) | 교환 기한, 같은 상품 여부, 재고를 확인해 처리안을 만든다 | 유형, 교환 사유, 주문 정보, 재고, 정책 | 처리안 | 규칙 | 정책의 조건이 명확하다 | 불량 사유이거나 사유를 판단할 수 없으면 넘긴다 |
| 판단(취소) | 주문 상태와 취소 범위를 확인해 처리안을 만든다 | 유형, 주문 정보, 정책 | 처리안 | 규칙 | 정책의 조건이 명확하다 | `cancel_partial`이면 넘긴다 |
| 승인(교환) | 교환 발송이 포함된 처리안을 확정한다 | 처리안 | 승인 또는 거절 | 사람(CS 담당자) | 교환 발송은 정책상 담당자 승인이 필요하다 | 교환 가능으로 판단된 모든 처리안 |
| 승인(취소) | 결제 취소가 포함된 처리안을 확정한다 | 처리안 | 승인 또는 거절 | 사람(CS 담당자) | 출고 전 전체 취소는 정책상 고객 요청만으로 가능하지만, 같은 상품 주문이 여러 건일 때 주문번호 추출이 틀리면 엉뚱한 주문이 취소되므로 운영 초기에는 담당자가 확인한다 | 출고 전 전체 취소 처리안 |
| 응답(주문번호 요청) | 접수에서 주문번호가 없으면 안내문 틀로 주문번호를 요청한다 | 누락 항목 | 고객 안내 | 규칙 | 안내 내용이 정해져 있다 | 없음 |
| 응답(교환) | 불가 안내는 안내문 틀로 보내고, 교환 안내는 처리안 기반 초안을 승인 때 함께 확인한 뒤 보낸다 | 확정된 처리안 | 고객 안내 | 규칙(불가 안내), LLM 초안 → 사람 확정(교환 안내) | 불가 사유는 정책 조항별로 정해져 있고, 교환 안내는 옵션과 배송비를 담아 고객별로 작성한다 | 사람에게 넘어간 문의는 담당자가 응답한다 |
| 응답(취소) | 불가 안내는 안내문 틀로 보내고, 승인된 취소는 주문 시스템에 반영한 뒤 결과를 안내한다 | 확정된 처리안 | 고객 안내, 취소 결과 | 규칙 | 불가 사유와 취소 결과의 안내 내용이 정해져 있다 | 사람에게 넘어간 문의는 담당자가 응답한다 |

## 3. 아직 정해지지 않은 사항

- 재고가 없을 때 재고가 있는 다른 옵션을 먼저 권할지, 선택지로만 함께 안내할지 정해져 있지 않다. 이 분해도는 선택지로 함께 안내한다(INQ-102).
- 출고 전 전체 취소를 언제부터 자동으로 집행할지는 주문번호 추출 정확도를 운영 데이터로 확인한 뒤 정한다.
- 재문의 여부를 확인할 문의 이력을 어디에 저장할지 정해야 한다.
