# 업무 분해도: 메일함 정리

- 작성자: 김성환
- 작성일: 2026-11-10
- 대상 업무 범위: 오후 9시에 작업이 시작된다. 받은 메일 중 광고,뉴스레터는 "나중에 읽기"로 이동, 청구메일은 금액과 납부기간을 지출기록표에 작성, 답장이 필요한 메일은 한줄로 요약해서 답장알림하고, 개인정보나 보안관련 메일은 확인알림, 나머지는 그대로 둔다.
- 사용한 자료: `data/메일 샘플.csv`

## 분류 유형 목록
### 메일 분류 유형

| 유형 값 | 뜻 | 처리 | 해당 메일 |
|---|---|---|---|
| `promotion` | 광고, 뉴스레터  | "나중에 읽기" 로 이동 | M01, M09 |
| `bill` | 청구서, 고지서 | 금액과 납부기간을 지출기록표에 작성| ... |
| `reply_needed` | 답장이 필요한 메일 | 한줄로 요약해서 알림 | ... |
| `security_check` | 보안관련 메일 | 보안 확인 알림 전송 | .. |
| `other` | 위 분류로 분류가 안되는 메일 | 그대로 둔다. | ... |

## 단계별 판단 주체

| 단계 | 하는 일 | 입력 | 결과 | 판단 주체 | 선택 이유 | 사람에게 넘기는 조건 |
|---|---|---|---|---|---|---|
| 접수 | 당일 0시 이후에 받은 메일들을 가져온다. | 메일함 | (당일)메일 목록 | 규칙  | `received_at` 필드의 값과 당일 날자를 비교해 선택할 수 있다. |  없다 |  
| 분류 | 메일 유형(위 다섯가지) 으로 분류한다. | `from`, ,`subject`, `snippet` |  5가지 분류 유형 중 하나| 규칙->LLM | 규칙: 특정키워드, 메일주소로 1차 분류한다. LLM: 규칙으로 분류 안될 경우 이용 | 없다 |
| 조회1 | 분류가 bill 인경우. 메일본문에서 청구금액과 기한을 추출 | `snippet` | 청구금액, 기한 | LLM -> 규칙 | 메일본문 형식이 자연어이고 발신자마다 다르므로 LLM 으로 추출. 추출한 금액이 숫자인지, 기한이 날짜 형식인지 규칙으로 검사 | 숫자와 기한이 검사를 통과못하면 사람이 직접 기록하도록 한다.  |
| 조회2 | 분류가 `bill` 인 경우. 청구서의 기록이 기록표에 이미 있는지 확인한다. | 조회1에서 조회한 금액, 기한, `from` | 기록 여부 | 규칙 | 지출기록표의 기록과 비교하면 결과가 정해진다. | 없음 |
| 판단 | `bill`: 청구금액, 기한등을 청구기록에 저장. `reply_needed`: 내용을 한줄로 요약 | bill: 청구금액, 기한, 발신인,   reply_needed: `snippet` | 저장(bill). 한줄요약내용(reply_needed) | 규칙(bill), LLM(한줄요약) | BILL은 조회한 값을 기반으로 기록지에 저장하는 것이므로 규칙기반. reply_needed는 자연어 문장을 요약하는 것이므로 LLM을 이용 | 없음 |
| 승인 | 없음 |  |  |  |  |  |
| 응답 | 폴더 이동(promotion), 청구서기록에 기록(bill), 알림발송(reply_needed, security_check)|분류유형, 대상메일(promotion), 금액/기한(bill), 요약문(reply_needed), 안내답변(security_check)  | 분류처리완료 로그  | 규칙 | 분류유형별로 처리 방법이 정해져 있다.  | 없음  |
