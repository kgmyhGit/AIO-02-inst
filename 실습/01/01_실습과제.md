# 1장 실습과제. 업무 자동화 방식과 n8n 사용 판단

# 개요

## 1. 이 실습을 통해 배울 것

이 장에서는 n8n을 실행하지 않는다. 실제 업무 자료를 단계로 나누고, 단계마다 누가 판단할지(규칙, LLM, 에이전트, 사람) 정하고, 자동화 범위를 확인한다. 개념은 [1장 이론](../../../01_업무자동화방식과n8n사용판단.md)에서 확인한다.

- 업무를 접수, 분류, 조회, 판단, 승인, 응답의 단계로 나눈다.
- 단계마다 알맞은 판단 주체를 근거와 함께 정한다.
- 사람에게 넘기는 조건을 관찰할 수 있는 사실로 적는다.
- 실제 요청이 분해도를 어떻게 지나가는지 확인해 자동화 범위를 정한다.

## 2. 실습 목차

| 실습 이름 | 종류 | 실습으로 익힐 것 |
|---|---|---|
| 1-1 메일함 정리 업무 분해 | 주제 실습(개인) | 끝난 상태 정의, 유형 목록, 단계별 판단 주체 |
| 1-2 식단 기록 업무 분해 | 주제 실습(개인) | 시작 계기에 따른 흐름 나누기, LLM 결과 검사, 자동화 범위 판단 |
| 1-3 배송과 반품 문의의 업무 분해 | 누적 프로젝트(함께하는 실습) | 업무 분해도, 사람에게 넘기는 조건, 처리 경로, 워크플로우 개념도 |
| 1-4 교환과 주문 취소 문의에 같은 기준 적용 | 누적 프로젝트(스스로 하는 실습) | 같은 기준을 다른 요청 유형과 메일 채널에 적용 |

1-1을 먼저 하고, 1-2는 1-1을 마친 뒤 어느 때나 할 수 있다. 1-3과 1-4는 가상의 온라인 쇼핑몰 '하루마켓'의 고객지원 업무를 다룬다. 여기서 만든 결과물은 2장에서 이어서 사용하므로 잘 보관한다.

1-3과 1-4의 결과물은 2장에서 데이터 형식과 승인·실패 경로를 설계하는 출발점이 된다. 2장에서는 풀이를 마친 뒤 받는 1-3·1-4의 예시 답안을 이어받는다. 자신의 결과물은 예시 답안과 비교해 다른 점을 표시해 둔다. 1-1의 메일함 정리와 1-2의 식단 기록은 2장 주제 실습(2-5, 2-1)의 소재로 다시 나온다. 2장 과제에서 필요한 내용을 다시 설명하므로 1장 결과물이 없어도 시작할 수 있다.

## 3. 공통사항

**진행 방식**

모든 실습은 같은 순서로 진행한다. 먼저 이 문서와 제공 파일만 보고 주어진 시간 동안 직접 해 본다. 시간이 끝나면 강사가 예시 답안을 보여 주며 왜 그렇게 되는지 설명한다. 자신의 결과물은 고치기 전 상태로 남겨 두고, 풀이와 비교해 다른 부분을 표시한다. 예시 답안과 달라도 이유가 맞으면 성립하는 답이 있으므로, 다른 점마다 자신의 이유를 적어 둔다.

**필요한 것**

- Markdown 파일을 편집할 수 있는 편집기. 표 작성이 불편하면 스프레드시트에서 작성한 뒤 옮겨도 된다.
- n8n 설치와 외부 서비스 계정은 필요하지 않으며 비용도 들지 않는다.
- CSV 파일은 UTF-8 인코딩이다. 스프레드시트에서 한글이 깨지면 가져오기 기능에서 인코딩을 UTF-8로 지정해 연다.

**결과물 저장**

자신의 작업 폴더 안에 `01/` 폴더를 만들고 결과물을 저장한다. 양식 파일을 복사한 뒤 실습별 결과물 이름으로 바꾸어 작성한다.

**업무 분해도 양식 읽기**

양식 1절의 표는 여섯 단계(접수, 분류, 조회, 판단, 승인, 응답)를 기본으로 행마다 일곱 칸을 채운다.

- **입력**과 **결과**에는 그 단계가 무엇을 받아 무엇을 넘기는지 적는다.
- **판단 주체**에는 `규칙`, `LLM`, `에이전트`, `사람` 중 하나를 적는다. 결과를 만드는 방식과 확정하는 주체가 다르면 `LLM → 사람 확정`처럼 함께 적는다.
- **사람에게 넘기는 조건**에는 자동 처리에서 벗어나 사람이 맡아야 하는 경우를 관찰할 수 있는 사실로 적는다. '이상하면'처럼 적지 않는다.
- 같은 단계가 여러 번 나오면 행을 추가하고 `조회 1`, `조회 2`처럼 번호를 붙인다. 없는 단계는 `없음`과 그 이유를 적는다.
- 요청 유형에 따라 처리가 갈라지면 공통 단계는 한 번만 적고, 갈라지는 단계부터 `판단(유형 A)`, `판단(유형 B)`처럼 행을 나눈다. 어느 행으로 갈지를 정하는 값은 갈라지기 직전 행의 결과에 드러나야 한다. 공통 단계가 거의 없거나 시작 계기가 다르면 표를 유형이나 흐름별로 나누어도 된다.

양식 2절의 표에는 실제 요청 하나하나가 그 단계들을 어떻게 지나가는지 적는다. 요청 유형 목록처럼 양식에 자리가 없는 표는 1절 앞에 더해 적는다.

# 1-1 - 메일함 정리 업무 분해

## 1. 실습 주제 및 상황

개인 메일함을 정리하는 작업을 자동화하려고 한다. 자동화하고 싶은 작업은 다음과 같다.

> 매일 저녁 9시에 그날 받은 메일을 정리한다. 광고와 뉴스레터는 '나중에 읽기' 폴더로 옮긴다. 청구서는 금액과 납부 기한을 지출 기록표에 적는다. 답장이 필요한 메일은 한 줄로 요약해 나에게 알림으로 보낸다.

## 2. 이 실습의 목적

같은 작업 안에서도 단계마다 알맞은 판단 주체가 다르다는 점을 확인한다.

관련 이론: [1.1 업무 분해도 - 업무를 단계로 나누기](../../../01_업무자동화방식과n8n사용판단.md#11-업무-분해도---업무를-단계로-나누기), [1.2 네 가지 판단 주체](../../../01_업무자동화방식과n8n사용판단.md#12-네-가지-판단-주체), [1.3 단계별 판단 주체를 정하는 기준](../../../01_업무자동화방식과n8n사용판단.md#13-단계별-판단-주체를-정하는-기준)

## 3. 관련 파일

- [`data/메일함_샘플.csv`](data/메일함_샘플.csv): 메일 12통. 필드는 `mail_id`, `received_at`, `from`, `subject`, `snippet`(본문 앞부분)이다.
- [`templates/업무분해도_양식.md`](templates/업무분해도_양식.md): 업무 분해도 작성 양식

## 4. 결과물

`01_업무분해도_메일함정리.md`: 대상 업무 범위, 유형 목록, 여섯 단계 분해도, 메일 3통의 처리 경로

다음을 만족해야 한다.

- 여섯 단계 모두 입력, 결과, 판단 주체, 선택 이유가 채워져 있다. 두지 않은 단계에는 두지 않은 이유가 적혀 있다.
- LLM을 쓴 단계마다 결과를 검사하는 규칙이나 결과가 틀렸을 때의 처리가 적혀 있다.
- 유형마다 자동으로 처리해도 되는지 판단한 근거가 있다.
- 에이전트를 쓰지 않았다면 쓰지 않은 이유를, 썼다면 경로를 미리 정할 수 없는 이유를 설명할 수 있다.

## 5. 해야 할 것

1. **대상 업무 범위 작성** 
   - 양식의 '대상 업무 범위'에 작업이 언제 시작해 어떤 상태가 되면 끝나는지 적는다. 샘플의 메일들이 모두 그 상태 중 하나로 끝나는지 확인한다.
2. **메일 샘플들을 보고 분류 유형 목록을 정한다.** 
   - 처리 방법이 달라지는 기준으로 유형을 나눈다. 제목뿐 아니라 보낸 사람과 본문도 읽는다. 유형을 정한 뒤에는 그 유형의 처리를 자동으로 해도 괜찮은지 메일마다 따져 본다. 다음 표를 채운다.

    | 유형 값 | 뜻 | 처리 | 해당 메일 |
    |---|---|---|---|
    |  |  |  |  |

3. **여섯 단계로 나누고 판단 주체를 정한다.** 양식의 1절 표를 채운다. 단계마다 [이론 1.3절의 다섯 가지 질문](../../../01_업무자동화방식과n8n사용판단.md#다섯-가지-질문)을 차례로 적용한다. 에이전트를 쓰지 않았다면 쓰지 않은 이유를 적는다.
4. **메일 3통으로 처리 경로를 확인한다.** 처리 경로가 서로 다르게 끝나는 메일 세 통을 골라 양식의 2절 표에 적는다.

## 6. 이어서 더 해 볼 만한 주제

**사진 폴더 매주 정리하기.** 스마트폰 사진 폴더를 매주 정리하는 작업을 분해한다. 스크린샷과 영수증 사진을 어떻게 나누고, 삭제는 누가 확인할지 정해 본다. 사진을 읽어야 나눌 수 있는 단계와 파일 정보만으로 나눌 수 있는 단계를 구분하고, 한 번 지우면 되돌리기 어려운 일에 사람의 확인을 어디에 둘지 판단한다.

**팀 공용 문의 메일함 나누기.** 팀 공용 문의 메일함에 들어온 메일을 담당자별로 나눈다. 규칙으로 나눌 메일, LLM이 판단할 메일, 팀장에게 넘길 메일을 정해 본다. 어느 담당자에게도 맞지 않는 메일과 담당자가 둘인 메일의 처리를 사람에게 넘기는 조건으로 적는다.

# 1-2 - 식단 기록 업무 분해

## 1. 실습 주제 및 상황

음식 사진으로 식단을 기록하는 작업을 자동화하려고 한다. 자동화하고 싶은 작업은 다음과 같다.

> 먹기 전에 음식 사진을 메신저로 보내면, 사진 속 음식과 대략적인 열량·단백질·나트륨을 식단 기록표에 적고 기록한 내용을 답장으로 받는다. 매일 저녁 9시에는 그날 기록을 모아 하루 목표와 비교한 리포트를 받는다.

하루 목표는 열량 2,000kcal, 단백질 100g, 나트륨 2,000mg으로 가정한다. 사진으로 추정한 영양 정보는 측정값이 아니며, 이 실습은 건강 조언이 아니라 기록 작업을 나누어 보는 연습이다.

## 2. 이 실습의 목적

실습 1-1의 메일함 정리는 대부분 규칙으로 처리할 수 있는 작업이었다. 식단 기록은 사진을 읽는 일이 중심이라 LLM이 결과를 만드는 단계가 많다. 이런 작업에서 LLM의 결과를 검사하는 규칙과 본인이 확인하는 조건을 어디에 둘지 정한다. 또한 시작하는 계기가 다른 일을 어떻게 나누어 분해하는지 확인한다.

관련 이론: [1.1](../../../01_업무자동화방식과n8n사용판단.md#11-업무-분해도---업무를-단계로-나누기)~[1.3절](../../../01_업무자동화방식과n8n사용판단.md#13-단계별-판단-주체를-정하는-기준), [1.6 자동화 범위와 사람의 책임, 도구 선택 근거](../../../01_업무자동화방식과n8n사용판단.md#16-자동화-범위와-사람의-책임-도구-선택-근거)

## 3. 관련 파일

- [`data/식단사진_메시지.csv`](data/식단사진_메시지.csv): 메시지 5건. 필드는 `message_id`, `received_at`, `caption`(사진과 함께 보낸 설명 문구, 없으면 빈 칸), `photo_note`(사진에 찍힌 내용)다. 설계만 하는 실습이라 사진 파일 대신 사진 내용을 글로 적었다.
- [`templates/업무분해도_양식.md`](templates/업무분해도_양식.md): 1절의 표를 복사해 표 두 개로 만든다.

## 4. 결과물

`01_업무분해도_식단기록.md`: 두 흐름의 시작 계기와 끝난 상태, 흐름별 여섯 단계 분해도, 사진 5건의 처리 경로, 아직 정해지지 않은 사항

다음을 만족해야 한다.

- 작업을 시작 계기에 따라 흐름으로 나누었고, 흐름마다 시작 계기와 끝난 상태가 적혀 있다.
- 두 흐름의 여섯 단계 모두 입력, 결과, 판단 주체, 선택 이유가 채워져 있다. 두지 않은 단계에는 두지 않은 이유가 적혀 있다.
- LLM이 결과를 만드는 단계마다 결과를 검사하는 규칙과 검사에 실패했을 때의 처리가 적혀 있다.
- 합계 계산과 목표 비교를 누가 맡는지와 그 이유가 적혀 있다.
- 리포트에 건강 조언을 넣을지를 자동화 범위로 판단한 내용이 있다.
- 사진 5건 모두 처리 경로를 설명할 수 있다.

## 5. 해야 할 것

1. **대상 업무 범위 작성**
   - 끝난 상태를 정하고 흐름을 나눈다.
   - 작업 설명(실습 주제 및 상황)에서 일을 시작하는 계기를 모두 찾는다. 계기마다 한 번 실행할 때의 입력과 끝난 상태를 적는다.

    | 구분 | (흐름 이름) | (흐름 이름) |
    |---|---|---|
    | **시작** |  |  |
    | **실행의 입력** |  |  |
    | **끝난 상태** |  |  |

2. **사진을 기록하는 흐름의 여섯 단계와 판단 주체를 정한다.** 
   - 첫 번째 표에 채운다. LLM이 결과를 만드는 단계마다 결과를 검사하는 규칙과, 검사에 실패했을 때 그 값을 버릴지 표시해서 남길지 정한다. 
3. **리포트 작성 흐름의 여섯 단계를 정하고 자동화 범위를 확인한다.** 
   - 두 번째 표에 채운다. 리포트에 LLM이 쓴 식단 조언을 넣을지 [이론 1.6절](../../../01_업무자동화방식과n8n사용판단.md#16-자동화-범위와-사람의-책임-도구-선택-근거)의 자동화 범위로 판단하고, 판단 이유를 적는다.
4. **사진 5장으로 처리 경로를 확인한다.** 
   - 양식의 2절 표에 5건을 모두 적는다. 분해도로 처리할 수 있지만 아직 정하지 않은 문제가 있으면 '아직 정해지지 않은 사항'에 적는다.

## 6. 이어서 더 해 볼 만한 주제

**영수증 사진으로 가계부 쓰기.** 영수증 사진을 보내면 가게 이름과 금액을 가계부에 적고, 매주 일요일에 주간 지출 요약을 받는다. LLM이 맡을 일과 규칙이 맡을 일을 나누어 본다. 금액을 잘못 읽었을 때 어떤 규칙으로 알아챌 수 있는지, 사진 처리와 주간 요약을 어떻게 다른 흐름으로 나눌지 함께 적는다.

**명함 사진으로 연락처 등록하기.** 받은 명함 사진을 보내면 이름, 회사, 연락처를 고객 연락처 목록에 등록한다. 잘못 읽은 연락처로 메일을 보내면 어떤 문제가 생기는지 생각해 보고, 본인이 확인할 조건을 정해 본다. 이미 있는 연락처가 다시 들어올 때의 처리도 정한다.

**회의 음성 메모로 할 일 정리하기.** 회의 뒤 녹음한 음성 메모에서 할 일과 담당자, 기한을 뽑아 표에 적는 작업을 분해한다. 음성을 글로 바꾸는 일, 할 일을 뽑는 일, 담당자에게 알리는 일의 판단 주체를 각각 정한다. 기한이 말로만 언급된 경우처럼 LLM 결과를 그대로 믿기 어려운 경우에 무엇을 사람에게 묻는지 적는다.

# 1-3 - 배송과 반품 문의의 업무 분해

## 1. 실습 주제 및 상황

하루마켓은 생활용품과 의류를 파는 가상의 온라인 쇼핑몰이다. 지금은 CS 담당자 두 명이 웹 문의 게시판과 메일로 들어오는 문의를 모두 직접 처리한다. 문의가 늘어 답변이 늦어지자 자동화를 검토하게 되었다.

**CS 담당자가 지금 하는 일**

CS 담당자는 웹 문의 한 건을 다음 순서로 처리한다.

1. 게시판에서 새 문의를 열어 고객 이름, 주문번호, 문의 내용을 확인한다. 주문번호가 없으면 고객에게 다시 묻는다.
2. 문의 내용을 읽고 배송 문의인지 반품 문의인지, 반품이라면 사유가 무엇인지 파악한다.
3. 주문 시스템에서 주문을 찾아 고객 이름이 일치하는지 확인하고, 주문 상태, 출고일, 수령일을 확인한다.
4. 날짜를 직접 세어 쇼핑몰 정책과 비교하고 처리 방법을 정한다. 배송이 늦어졌으면 택배사에 확인하고, 상품 불량을 신고한 문의는 사진 등으로 사실을 확인한다.
5. 반품을 받아들일 때는 환불 금액을 확정해 승인한다. 그 뒤 고객에게 도착 예정일, 반품 절차, 반품이 불가능한 이유 등을 답변으로 보낸다.

배송 일정 문의처럼 조회한 사실을 정해진 문구로 알려 주면 끝나는 문의에도 이 과정을 거치므로, 담당자의 시간이 많이 든다.

**자동화에서 바라는 것**

정해진 안내로 끝나는 문의에 드는 담당자의 시간을 줄여 답변을 앞당기려고 한다. 다만 쇼핑몰 정책은 다음 조건을 정해 두었으므로 자동화한 뒤에도 지켜야 한다.

- 환불 집행은 CS 담당자의 승인 후에만 진행한다.
- 주문 정보는 주문번호와 고객 이름이 모두 일치할 때만 안내한다.
- 분쟁이나 신고를 언급하거나 같은 건으로 두 번 이상 다시 문의하면 CS 담당자에게 즉시 넘긴다.

나머지 일을 어느 단계까지 자동화하고, 각 단계를 규칙, LLM, 에이전트, 사람 중 누구에게 맡길지는 이 실습에서 정한다.

이 실습에서는 **웹으로 들어온 배송·반품 문의 8건을 분석해 업무 분해도를 만들고, n8n 워크플로우 개념도로 옮겨 본다.**

# 1-4 - 교환과 주문 취소 문의에 같은 기준 적용

## 1. 실습 주제 및 상황

하루마켓에는 메일로 들어오는 교환·주문 취소 문의가 있다. 지금은 CS 담당자 두 명이 웹 문의 게시판과 메일로 들어오는 문의를 모두 직접 처리한다. 문의가 늘어 답변이 늦어지자 자동화를 검토하게 되었다.

**CS 담당자가 지금 하는 일**

CS 담당자는 문의 메일 한 통을 다음 순서로 처리한다.

1. 메일을 열어 보낸 고객을 확인하고, 제목과 본문에서 주문번호, 원하는 옵션, 취소 수량을 찾아 읽는다. 주문번호를 찾을 수 없으면 고객에게 다시 묻는다.
2. 메일 내용을 읽고 교환 문의인지 취소 문의인지 파악한다. 교환이라면 무엇으로 바꾸려는지, 취소라면 주문 전체인지 일부 수량인지 확인한다.
3. 주문 시스템에서 주문을 찾아 고객 이름이 일치하는지 확인하고, 주문 상태와 수령일을 확인한다. 교환 문의는 원하는 옵션의 재고도 확인한다.
4. 쇼핑몰 정책과 비교해 처리 방법을 정한다. 교환은 신청 기한, 교환 대상, 재고, 배송비 부담을 따지고, 취소는 주문 상태와 취소 범위를 따진다.
5. 교환을 받아들일 때는 교환 상품 발송을 승인하고, 취소할 수 있는 주문은 주문 시스템에 취소를 반영한다. 그 뒤 고객에게 처리 결과나 처리할 수 없는 이유와 다음 절차를 답장으로 보낸다.

메일은 형식이 정해져 있지 않아 찾아 읽는 데 시간이 든다. 또한 재고가 없거나 기한이 지나 정해진 안내로 끝나는 문의에도 이 과정을 거쳐야 한다.

**자동화에서 바라는 것**

정해진 안내로 끝나는 문의에 드는 담당자의 시간을 줄여 답변을 앞당기려고 한다. 다만 쇼핑몰 정책은 다음 조건을 정해 두었으므로 자동화한 뒤에도 지켜야 한다.

- 교환 상품 발송은 CS 담당자의 승인 후에만 진행한다.
- 주문의 일부 수량 취소는 CS 담당자가 처리한다.
- 주문 정보는 주문번호와 고객 이름이 모두 일치할 때만 안내한다.
- 분쟁이나 신고를 언급하거나 같은 건으로 두 번 이상 다시 문의하면 CS 담당자에게 즉시 넘긴다.

어느 단계까지 자동화하고, 각 단계를 규칙, LLM, 에이전트, 사람 중 누구에게 맡길지는 이 실습에서 정한다.

이 실습에서는 **메일로 들어온 교환·취소 문의 내용을 분석해 업무 분해도를 만든다.**
## 2. 이 실습의 목적

같은 기준을 다른 요청 유형과 메일 채널에 적용하면 업무 분해도의 어디가 달라지는지 확인한다.

## 4. 결과물

- `01_업무분해도_교환취소.md`: 요청 유형 목록, 여섯 단계 업무 분해도, 문의 8건의 처리 경로, 아직 정해지지 않은 사항

다음을 만족해야 한다.

- 문의 8건 모두 정책에 비춘 결론이 있고, 날짜 계산과 재고 확인이 자료와 일치한다.
- 교환과 주문 취소의 정책 차이가 판단 단계와 승인 단계에 반영되어 있다.
- 사람에게 넘기는 조건이 모두 관찰할 수 있는 사실로 적혀 있다.
- 주문 정보 안내와 주문 취소가 정책의 본인 확인 기준을 지킨다.
- 고객 요청만으로 집행할 수 있는 처리를 자동으로 할지 사람 확인 후 할지 선택하고, 그 이유를 설명한다.
- 정책에 없어 가정한 내용이 가정으로 표시되어 있다.

## 5. 해야 할 것

진행 방법은 실습 1-3의 1~3단계를 참고한다. 다음은 다르거나 반드시 지켜야 할 사항이다.

- 실습 1-3의 결과물을 복사해 고치지 말고 `교환취소_문의.csv`의 문의 8건을 직접 분석해 작성한다.
- `교환취소_문의.csv`는 메일로 들어온 문의를 표로 정리해서 옮긴 목록이다. 실제 메일에는 주문번호 칸이 따로 없어 본문이나 제목에서 주문번호를 찾아야 한다. 이 차이를 업무 분해도의 접수 단계에 반영한다.

## 6. 이어서 더 해 볼 만한 주제

**부분 취소를 자동화할 수 있는 조건 따져 보기.** 정책은 일부 수량 취소를 담당자가 처리하도록 정했다. 어떤 시스템 기능과 확인 수단이 있으면 일부를 자동으로 처리할 수 있을지 조건을 적는다. 잘못 처리했을 때 되돌리는 비용을 함께 적어, 조건이 갖춰져도 사람이 맡는 편이 나은 경우가 있는지 판단한다.

**채널이 하나 더 늘어날 때의 분해도.** 같은 문의가 고객센터 전화 메모로도 들어온다고 가정한다. 접수와 분류 단계에서 달라지는 점을 적고, 웹과 메일과 전화 메모의 분해도를 하나로 합칠지 따로 둘지 판단한다. 공통 단계와 채널별 단계를 나눈 표를 만들어 본다.

**교환과 취소가 섞인 문의 다루기.** "사이즈를 바꿔 주시고, 안 되면 취소해 주세요"처럼 두 요청이 조건으로 이어진 문의를 다섯 건 만들어 본다. 지금 유형 목록으로 어떻게 처리되는지 따라가고, 유형을 더할지 사람에게 넘길지 비교한다. 고객에게 먼저 물어보아야 하는 경우의 조건도 적는다.
