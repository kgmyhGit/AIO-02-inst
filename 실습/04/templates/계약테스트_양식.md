> 워크플로우나 에이전트의 결과가 결과 계약을 지키는지 사례별로 확인하는 양식이다. 4장 실습 4-6, 4-7에서 쓴다.
> 파일 이름은 `04_계약테스트_배송안내.md`처럼 `장번호_계약테스트_대상.md`로 한다.
> 2장 인수 조건을 모델이 들어간 흐름에 적용한 것이다. 이론 4.6절을 참고한다.

## 2. 테스트 케이스

정상, 미존재, 인증 실패는 반드시 넣는다. 같은 사례를 여러 번 실행했으면 회차마다 줄을 나누어 적는다.

| 테스트_ID | 사례 유형 | 회차 | 입력데이터 | 기대결과 | 결과 허용 기준 | 실제응답결과 | 도구 호출 수 | 걸린시간 | 판정 |
|---|---|---|---|---|---|---|---|---|---|
| | | 1 | | | | | | | |
| | | 2 | | | | | | | |
| | | 3 | | | | | | | |

| 열 | 적는 내용 |
|---|---|
| **사례 유형** | 정상, 미존재, 인증 실패, 권한이 없는 대상처럼 이 사례가 하려는 테스트의 유형 |
| **기대결과** | 정확히 일치해야 하는 값 |
| **결과 허용 기준** | 에이전트의 답변은 실행마다 달라지므로 문장 대신 기준을 적는다. 어떤 뜻의 결과여야 하는지, 어떤 값이 있으면 안 되는지 등과 같은 기준을 적는다 |
| **실제응답결과** | 워크플로우의 실제 응답을 적는다. |
| **도구 호출 수** | 실행 기록에서 읽은 도구 호출 횟수 |
| **걸린시간** | 실행 기록에서 읽은 시간 |
| **판정** | 통과 또는 실패. 기대결과와 결과 허용 기준을 지켰는지, 검증 규칙의 결과와 걸린시간이 받아들일 만한지를 종합해 정한다. 인증 실패처럼 **실패해야 옳은 사례**는 답을 지어내지 않고 정해진 실패 결과로 끝나면 통과다 |
