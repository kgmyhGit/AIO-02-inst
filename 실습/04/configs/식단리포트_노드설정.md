# 실습 4-4 식단 기록과 식단 리포트의 노드 설정

> 실습 4-4에서 만드는 두 워크플로우 `식단 기록`과 `식단 리포트`의 완성 설정이다. 지시문, JSON Schema, Code 노드의 코드는 예시 답안 워크플로우와 같다. 노드 이름은 표에 적은 그대로 붙인다. Code 노드와 표현식이 다른 노드를 이름으로 참조하기 때문이다.
>
> 기록 행의 열과 형식은 2장 [`02_기록설계_식단기록.md`](../../../02/실습결과_산출물_학생제공/02_기록설계_식단기록.md)의 데이터 계약(2.1 LLM 사진 분석 결과, 2.2 식단기록 행 계약)을 따른다.

## 0. Data Table `식단기록`

n8n 왼쪽 메뉴의 Overview에서 Data tables 탭을 열고 새 표를 만든다. 이름은 `식단기록`이다. 두 워크플로우는 이 이름으로 표를 찾는다(Data table 칸의 By Name).

| 열 이름 | 타입 | 2장 계약 |
|---|---|---|
| `record_id` | String | `R-` 뒤 숫자 세 자리 |
| `recorded_at` | String | ISO 8601, `+09:00` 포함 |
| `date` | String | `YYYY-MM-DD`, 한국 시간 날짜 |
| `meal_type` | String | `breakfast`, `lunch`, `dinner`, `snack` |
| `food_name` | String | 빈 문자열이 아님 |
| `amount` | String | 자유 표기, 없으면 빈 칸 |
| `calories` | Number | 0 이상, 모르면 빈 칸 |
| `protein_g` | Number | 0 이상, 모르면 빈 칸 |
| `sodium_mg` | Number | 0 이상, 모르면 빈 칸 |
| `confidence` | String | `high`, `medium`, `low` |
| `message_id` | String | 원본 메시지 식별자. 폼 제출이면 `F-` + 실행 번호 |

리포트를 먼저 시험하려면 표를 만들 때 CSV 가져오기로 [`식단기록_데이터테이블.csv`](../data/식단기록_데이터테이블.csv)를 넣는다. 2장 2.3절에서 계약을 적용해 고친 기록 6행이다. 가져온 뒤 세 숫자 열의 타입이 Number인지 확인한다. String으로 잡혔으면 표를 지우고 위 표대로 열을 직접 만든 뒤 CSV를 다시 넣는다. 날짜 열을 Date 타입으로 만들지 않는다. 날짜 비교는 Code 노드가 문자열을 읽어 한다.

## 1. 워크플로우 `식단 기록`

워크플로우 Settings에서 Timezone을 `Asia/Seoul`로 둔다.

**연결 순서**

```text
식단 사진 받기 → 사진 분석 → 분석 검사 → 음식 있음?
  true  → 마지막 번호 조회 → 기록 행 만들기 → 식단기록 추가 → 답장 만들기 → 기록 결과 안내
  false → 기록 안 함 안내
사진 분석의 Chat Model 연결점 ← OpenAI Chat Model, Output Parser 연결점 ← 분석 결과 형식
```

### 1-1. `n8n Form Trigger` — 이름: 식단 사진 받기

| 파라미터 | 값 |
|---|---|
| Form Title | `식단 기록` |
| Form Description | `먹은 음식의 사진을 한 장 올린다. 끼니를 적으면 그 값으로 기록한다.` |
| Form Elements 1 | Field Name `photo` / Label `음식 사진` / Element Type File / Multiple Files 끔 / Accepted File Types `.jpg,.jpeg,.png,.webp` / Required Field 켬 |
| Form Elements 2 | Field Name `caption` / Label `설명 문구(예: 아침, 점심, 저녁, 간식)` / Element Type Text |

Field Name이 바이너리의 이름이 된다. `photo`로 두어야 1-2의 Image Data Field Name과 맞는다. 제출한 시각은 출력의 `submittedAt`에 들어온다.

### 1-2. `Basic LLM Chain` — 이름: 사진 분석

| 파라미터 | 값 |
|---|---|
| Source for Prompt (User Message) | Define below |
| Prompt (User Message) | 아래 사용자 메시지 |
| Require Specific Output Format | 켬 |
| Chat Messages → Prompt 1 | Type Name or ID: System / Message: 아래 시스템 메시지 |
| Chat Messages → Prompt 2 | Type Name or ID: User / Message Type: Image (Binary) / Image Data Field Name: `photo` / Image Details: Auto |
| Settings → Retry On Fail | 켬, Max Tries `2` |

Retry On Fail은 2장 계약 2.1의 "한 번 다시 분석"에 해당한다. 모델의 답이 1-4의 형식에 맞지 않아 노드가 실패하면 한 번 더 부른다.

사용자 메시지(Expression)

```text
받은 시각(한국 시간): {{ DateTime.fromISO($json.submittedAt).setZone('Asia/Seoul').toFormat('yyyy-MM-dd HH:mm') }}
설명 문구: {{ $json.caption || '(없음)' }}

사진 속 음식을 분석해 정해진 형식으로 답한다.
```

시스템 메시지

```text
당신은 음식 사진을 보고 음식별 분량과 영양 값을 추정하는 도우미다.

규칙
- 사진에 음식이 없으면 is_food를 false, foods를 빈 배열로 낸다.
- 사진에 보이는 음식을 하나씩 나누어 foods에 넣는다.
- meal_type은 breakfast, lunch, dinner, snack 중 하나다. 설명 문구에 끼니가 있으면 그것을 따르고, 없으면 null로 둔다.
- calories(kcal), protein_g(g), sodium_mg(mg)는 숫자로만 적는다. "약", 단위, 범위를 넣지 않는다.
- 추정할 수 없는 값은 0으로 채우지 말고 null로 둔다. 0은 실제로 0일 때만 쓴다.
- confidence는 high, medium, low 중 하나다. 가려지거나 양을 가늠하기 어려우면 low로 둔다.
- 합계를 계산하지 않는다. 합계는 워크플로우가 계산한다.
- 문자열은 한국어로 쓴다.
```

### 1-3. `OpenAI Chat Model` — 이름: OpenAI Chat Model

`사진 분석`의 Chat Model 연결점에 붙인다. Credential은 `OpenAI 실습`, Model은 `gpt-6-luna`, Options는 기본값이다.

### 1-5. `Code` — 이름: 분석 검사

Mode는 Run Once for All Items, Language는 JavaScript다.

```javascript
// 2장 데이터 계약 2.1을 규칙으로 검사한다. 모델의 결과를 그대로 기록하지 않는다.
const out = $input.first().json.output ?? {};
const form = $('식단 사진 받기').first().json;
const received = DateTime.fromISO(form.submittedAt).setZone('Asia/Seoul');

const MEALS = ['breakfast', 'lunch', 'dinner', 'snack'];
const LEVELS = ['high', 'medium', 'low'];
const issues = [];

// 받은 시각으로 끼니를 정한다(05:00~10:59 아침, 11:00~15:59 점심, 16:00~20:59 저녁, 그 밖 간식)
function mealByTime(dt) {
  const h = dt.hour;
  if (h >= 5 && h < 11) return 'breakfast';
  if (h >= 11 && h < 16) return 'lunch';
  if (h >= 16 && h < 21) return 'dinner';
  return 'snack';
}

// is_food가 불리언이 아니면 기록하지 않는다(다시 분석하는 일은 '사진 분석'의 Retry On Fail이 맡는다)
if (typeof out.is_food !== 'boolean') {
  issues.push('분석 결과에서 음식 여부를 읽지 못해 기록하지 않았습니다.');
}

// meal_type이 허용 값이 아니면 받은 시각으로 정한다
let mealType = out.meal_type;
if (!MEALS.includes(mealType)) mealType = mealByTime(received);

const foods = [];
for (const f of Array.isArray(out.foods) ? out.foods : []) {
  const name = typeof f.food_name === 'string' ? f.food_name.trim() : '';
  if (!name) {
    issues.push('이름이 없는 음식이 있어 그 음식은 기록하지 않았습니다.');
    continue;
  }
  let confidence = LEVELS.includes(f.confidence) ? f.confidence : 'low';
  const food = { food_name: name, amount: typeof f.amount === 'string' && f.amount.trim() ? f.amount.trim() : null };
  for (const key of ['calories', 'protein_g', 'sodium_mg']) {
    const v = f[key];
    if (v === null || v === undefined) {
      food[key] = null;                       // 모르는 값은 null(빈 칸)로 둔다. 0으로 채우지 않는다
    } else if (typeof v === 'number' && Number.isFinite(v) && v >= 0) {
      food[key] = v;
    } else {
      food[key] = null;                       // 숫자가 아니거나 음수면 null로 바꾸고 확신도를 낮춘다
      confidence = 'low';
      issues.push(`${name}의 ${key} 값(${v})이 숫자가 아니어서 비워 두었습니다.`);
    }
  }
  food.confidence = confidence;
  foods.push(food);
}

return [{
  json: {
    is_food: out.is_food === true && foods.length > 0,
    meal_type: mealType,
    foods,
    summary: out.summary ?? '',
    issues,
    received_at: received.toFormat("yyyy-MM-dd'T'HH:mm:ssZZ"),
    date: received.toFormat('yyyy-MM-dd'),        // 한국 시간의 날짜
    message_id: 'F-' + $execution.id,             // 폼 제출 한 번 = 메시지 하나
  },
}];
```

| 2장 계약 2.1의 규칙 | 코드에서 하는 일 |
|---|---|
| `is_food`가 불리언이 아니면 기록하지 않고 알린다 | `issues`에 이유를 넣고 `is_food`를 false로 낸다 |
| `meal_type`이 목록 밖이면 받은 시각으로 정한다 | `mealByTime()` |
| 숫자가 아니면 null로 바꾸고 `confidence`를 `low`로 낮춘다 | `calories`, `protein_g`, `sodium_mg` 검사 |
| `confidence`가 목록 밖이면 `low` | `LEVELS.includes()` |
| `food_name`이 비면 그 음식만 기록하지 않고 알린다 | `continue`와 `issues` |
| `date`는 `recorded_at`의 한국 시간 날짜 | `setZone('Asia/Seoul')` |

### 1-8. `Code` — 이름: 기록 행 만들기

Mode는 Run Once for All Items다.

```javascript
// 검사를 통과한 음식을 2장 계약 2.2의 기록 행으로 펼친다. 음식 하나 = 행 하나
const a = $('분석 검사').first().json;

// 이미 있는 record_id 중 가장 큰 번호 다음부터 매긴다
const last = $input.all()
  .map((i) => Number(String(i.json.record_id ?? '').replace('R-', '')))
  .filter((n) => Number.isInteger(n))
  .reduce((m, n) => Math.max(m, n), 0);

let next = last + 1;
return a.foods.map((f) => ({
  json: {
    record_id: 'R-' + String(next++).padStart(3, '0'),
    recorded_at: a.received_at,
    date: a.date,
    meal_type: a.meal_type,
    food_name: f.food_name,
    amount: f.amount,
    calories: f.calories,
    protein_g: f.protein_g,
    sodium_mg: f.sodium_mg,
    confidence: f.confidence,
    message_id: a.message_id,
  },
}));
```

### 1-10. `Code` — 이름: 답장 만들기

Mode는 Run Once for All Items다.

```javascript
// 기록한 행으로 답장 한 개를 만든다. 숫자는 기록한 값을 그대로 쓰고 다시 계산하지 않는다
const rows = $input.all().map((i) => i.json);
const a = $('분석 검사').first().json;
const MEAL = { breakfast: '아침', lunch: '점심', dinner: '저녁', snack: '간식' };
const show = (v, unit) => (v === null || v === undefined || v === '' ? '모름' : v + unit);

const lines = rows.map((r) =>
  `${r.record_id} ${r.food_name}(${r.amount ?? '분량 모름'}) ` +
  `열량 ${show(r.calories, 'kcal')} · 단백질 ${show(r.protein_g, 'g')} · 나트륨 ${show(r.sodium_mg, 'mg')}` +
  (r.confidence === 'low' ? ' [확인 필요]' : '')
);
const lowCount = rows.filter((r) => r.confidence === 'low').length;

const message = [
  ...lines,
  '',
  lowCount > 0
    ? `확인이 필요한 항목이 ${lowCount}개 있습니다. 값이 틀리면 기록표에서 직접 고쳐 주세요.`
    : '모든 항목을 기록했습니다.',
  ...a.issues.map((s) => '- ' + s),
].join('\n');

return [{ json: { title: `${a.date} ${MEAL[a.meal_type]} 기록 완료`, message } }];
```

## 2. 워크플로우 `식단 리포트`

워크플로우 Settings에서 Timezone을 `Asia/Seoul`로 둔다.

**연결 순서**

```text
매일 21시 → 리포트 설정 → 기간 기록 조회 → 하루 집계 → 기록 있음?
  true  → 한마디 조언 → 리포트 작성
  false → 기록 없음 안내
한마디 조언의 Chat Model 연결점 ← OpenAI Chat Model
```

### 2-1. `Schedule Trigger` — 이름: 매일 21시

Trigger Interval은 Days, Trigger at Hour는 `9pm`이다. 만드는 동안은 편집 화면에서 직접 실행한다.

### 2-2. `Edit Fields (Set)` — 이름: 리포트 설정

Mode는 Manual Mapping이다.

| 이름 | 타입 | 값 |
|---|---|---|
| `report_date` | String | `{{ $now.setZone('Asia/Seoul').toFormat('yyyy-MM-dd') }}` |
| `cutoff_hour` | Number | `21` |
| `target_calories` | Number | `2000` |
| `target_protein_g` | Number | `100` |
| `target_sodium_mg` | Number | `2000` |

하루 목표는 1·2장 예시 답안의 가정과 같다. 시험할 때는 `report_date`를 `2026-09-10`처럼 고정한 날짜로 바꾼다.

### 2-3. `Data Table` — 이름: 기간 기록 조회

| 파라미터 | 값 |
|---|---|
| Resource / Operation | Row / Get Row(s) |
| Data table | By Name `식단기록` |
| Must Match | Any Condition |
| Conditions 1 | Column `date` / Condition Equals / Value `{{ $json.report_date }}` |
| Conditions 2 | Column `date` / Condition Equals / Value `{{ DateTime.fromISO($json.report_date).minus({ days: 1 }).toFormat('yyyy-MM-dd') }}` |
| Return All | 켬 |
| Settings → Always Output Data | 켬 |

리포트 기간이 전날 21시부터이므로 전날 날짜의 행도 읽는다. 기간을 정확히 고르는 일은 2-4가 한다.

### 2-4. `Code` — 이름: 하루 집계

Mode는 Run Once for All Items다.

```javascript
// 리포트 기간의 행을 고르고 합계를 낸다. 계산은 규칙이 한다(1장 분해도, 2장 2.4)
const s = $('리포트 설정').first().json;
const end = DateTime.fromISO(s.report_date, { zone: 'Asia/Seoul' }).set({ hour: s.cutoff_hour, minute: 0, second: 0, millisecond: 0 });
const start = end.minus({ days: 1 });              // 전날 21:00 이상 ~ 당일 21:00 미만

const rows = $input.all()
  .map((i) => i.json)
  .filter((r) => r.record_id)                      // Always Output Data가 만든 빈 아이템 제외
  .filter((r) => {
    const t = DateTime.fromISO(r.recorded_at);
    return t >= start && t < end;
  });

// 빈 칸(null)은 합계에서 빼고 따로 센다. 표에서 읽은 값은 숫자로 바꾸어 계산한다
const num = (v) => (v === null || v === undefined || v === '' ? null : Number(v));
function total(key) {
  let sum = 0;
  const unknown = [];
  for (const r of rows) {
    const v = num(r[key]);
    if (v === null || Number.isNaN(v)) unknown.push(r.record_id);
    else sum += v;
  }
  return { sum: Math.round(sum * 10) / 10, unknown };
}
const cal = total('calories');
const pro = total('protein_g');
const sod = total('sodium_mg');
const pct = (x, t) => (Number(t) > 0 ? Math.round((x / Number(t)) * 100) : null);

return [{
  json: {
    report_date: s.report_date,
    period: `${start.toFormat('MM-dd HH:mm')} ~ ${end.toFormat('MM-dd HH:mm')}`,
    has_records: rows.length > 0,
    record_count: rows.length,
    totals: { calories: cal.sum, protein_g: pro.sum, sodium_mg: sod.sum },
    targets: { calories: s.target_calories, protein_g: s.target_protein_g, sodium_mg: s.target_sodium_mg },
    percent: {
      calories: pct(cal.sum, s.target_calories),
      protein_g: pct(pro.sum, s.target_protein_g),
      sodium_mg: pct(sod.sum, s.target_sodium_mg),
    },
    unknown: { calories: cal.unknown, protein_g: pro.unknown, sodium_mg: sod.unknown },
    low_count: rows.filter((r) => r.confidence === 'low').length,
    record_ids: rows.map((r) => r.record_id),
  },
}];
```

### 2-8. `Code` — 이름: 리포트 작성

Mode는 Run Once for All Items다.

```javascript
// 숫자는 '하루 집계'의 값을 정해진 틀에 채운다. 모델의 문장은 끝에 덧붙이기만 한다
const g = $('하루 집계').first().json;
const advice = String($json.text ?? '').trim() || '(조언을 만들지 못했습니다. 숫자 리포트만 보냅니다.)';

function line(label, key, unit) {
  const u = g.unknown[key].length;
  const note = u > 0 ? `, 최소치 · 값을 모르는 항목 ${u}개` : '';
  return `${label} ${g.totals[key]}${unit} / 목표 ${g.targets[key]}${unit} (${g.percent[key]}%${note})`;
}

const report = [
  `[${g.report_date} 식단 리포트] ${g.period}, 기록 ${g.record_count}개`,
  line('열량', 'calories', 'kcal'),
  line('단백질', 'protein_g', 'g'),
  line('나트륨', 'sodium_mg', 'mg'),
  ...(g.low_count > 0 ? [`확인이 필요한 항목 ${g.low_count}개`] : []),
  '',
  advice,
].join('\n');

return [{ json: { report_date: g.report_date, report } }];
```
