# 실습 4-3 칼로리 기록과 일일 리포트의 노드 설정

> 실습 4-3에서 만드는 두 워크플로우 `01_칼로리기록_사진분석`과 `02_일일리포트_건강조언`의 완성 설정이다. 워크플로우 01의 지시문, JSON Schema, Code 노드의 코드는 `다양한실습샘플/칼로리추적기/`의 워크플로우와 같다. 워크플로우 02는 그 샘플의 Code 노드를 전용 노드로 바꾸고 리포트를 Gmail로 보내도록 다듬은 구성이다. 노드 이름은 표에 적은 그대로 붙인다. Code 노드와 표현식이 다른 노드를 이름으로 참조하기 때문이다.
>
> 예시 답안과 다르게 둔 곳은 두 군데다. 모델은 이 장의 공통 기준대로 `gpt-6-luna`로 고르고, 자격 증명은 각자 만든 것을 고른다. 예시 답안 파일의 스프레드시트 ID, 자격 증명 ID는 만든 사람의 것이므로 그대로 쓸 수 없다.

## 0. 사전 준비

### 0-1. 스프레드시트

Google Drive에 새 스프레드시트를 만들고 이름을 `식단`으로 붙인다. 시트 탭 두 개를 아래 이름으로 만들고, 1행에 열 이름을 정확히 이대로 적는다. 두 워크플로우는 이 열 이름으로만 이어진다.

시트 `식단기록` (워크플로우 01이 쓰고, 02가 읽는다)

| 열 | 열 이름 | 의미 | 예시 |
|---|---|---|---|
| A | `date` | 기록 날짜(한국 시간) | 2026-09-07 |
| B | `time` | 기록 시각 | 12:40 |
| C | `meal_type` | 아침, 점심, 저녁, 간식 | 점심 |
| D | `food_name` | 음식 이름 | 김치찌개 |
| E | `amount` | 추정 분량 | 1인분(400g) |
| F | `calories` | 칼로리(kcal) | 250 |
| G | `carbs_g` | 탄수화물(g) | 12.5 |
| H | `protein_g` | 단백질(g) | 18.2 |
| I | `fat_g` | 지방(g) | 14.1 |
| J | `sodium_mg` | 나트륨(mg) | 1450 |
| K | `confidence` | 추정 확신도(높음, 중간, 낮음) | 중간 |
| L | `chat_id` | 보낸 사람의 텔레그램 chat_id | 123456789 |
| M | `message_id` | 텔레그램 메시지 번호 | 57 |

A열과 B열은 서식을 일반 텍스트로 바꿔 둔다(서식 > 숫자 > 일반 텍스트). 그대로 두면 시트가 `2026-09-07`을 날짜로 바꿔 저장해서, 워크플로우 02의 날짜 필터와 값이 맞지 않을 수 있다.

시트 `프로필` (워크플로우 02가 읽는다. 1행은 열 이름, 2행에 값 한 줄)

| 열 이름 | 의미 | 예시 |
|---|---|---|
| `name` | 이름 또는 별칭 | 홍길동 |
| `height_cm` | 키 | 175 |
| `weight_kg` | 체중 | 72 |
| `target_calories` | 하루 목표 칼로리(kcal) | 2000 |
| `target_carbs_g` | 하루 목표 탄수화물(g) | 275 |
| `target_protein_g` | 하루 목표 단백질(g) | 100 |
| `target_fat_g` | 하루 목표 지방(g) | 60 |
| `target_sodium_mg` | 하루 목표 나트륨(mg) | 2000 |
| `goal` | 목표 한 줄 | 3개월간 3kg 감량, 근육 유지 |

목표값은 실습용 예시다. 리포트 워크플로우는 목표값(`target_`으로 시작하는 다섯 열)을 프롬프트에 넣는다.

## 1. 워크플로우 `01_칼로리기록_사진분석`

**연결 순서**

```text
Telegram Trigger → 사진인가?
  true  → 음식 분석 → 음식 있음?
```

### 1-4. `Basic LLM Chain` — 이름: 음식 분석

| 설정 | 값 |
|---|---|
| Source for Prompt (User Message) | Define below |
| Require Specific Output Format | 켬 |
| Chat Messages | 아래 두 개를 순서대로 추가 |

Prompt (User Message), Expression:

```text
=현재 시각(한국): {{ $now.setZone('Asia/Seoul').toFormat('yyyy-MM-dd HH:mm') }}
사용자 설명(캡션): {{ $json.message.caption || '(없음)' }}

위 사진의 음식을 분석해 주십시오.
```

Chat Messages 1: Type Name or ID를 `System`으로 두고 Message에 아래를 넣는다.

```text
당신은 영양사입니다. 사용자가 보낸 음식 사진을 보고 음식별 칼로리와 영양 성분을 추정합니다.

규칙
- 사진에 보이는 음식을 하나씩 나누어 목록으로 만듭니다. 한 접시에 여러 음식이 있으면 각각 분리합니다.
- 분량은 사진의 그릇 크기와 일반적인 1인분 기준으로 추정하고, 추정 근거가 되는 분량(g 또는 개수)을 amount에 적습니다.
- 칼로리와 영양 성분(탄수화물, 단백질, 지방, 나트륨)은 한국 식품의약품안전처 식품영양성분 DB의 일반적인 값을 기준으로 추정합니다.
- 확신이 낮은 항목은 confidence를 "낮음"으로 표시합니다. 모르는 값을 0으로 채우지 말고 가장 그럴듯한 추정값을 적습니다.
- meal_type은 사용자의 설명(캡션)이 있으면 그것을 우선하고, 없으면 현재 시각(한국 시간)을 기준으로 아침(05~10시), 점심(11~14시), 저녁(17~21시), 그 외 간식으로 정합니다.
- 사진에 음식이 전혀 없으면 is_food를 false로, foods를 빈 배열로 반환합니다.
- 모든 문자열은 한국어로 작성합니다.
```

Chat Messages 2: Type Name or ID를 `User`, Message Type을 `Image (Binary)`로 둔다. Image Data Field Name은 기본값 `data`를 그대로 둔다. 1-1에서 생긴 바이너리 이름과 같아야 한다.

### 1-9. `Code` — 이름: 행 만들기

Mode는 Run Once for All Items, Language는 JavaScript다.

```javascript
// 음식 분석 결과(output.foods)를 시트에 넣을 행(row) 단위로 펼칩니다.
// - 입력: Basic LLM Chain 1개 아이템 { output: { meal_type, foods: [...], summary } }
// - 출력: 음식 1개 = 아이템 1개 (시트의 1행)
const analysis = $input.first().json.output;
const msg = $('Telegram Trigger').first().json.message;

// 한국 시간 기준 날짜/시간 (Luxon)
const now = $now.setZone('Asia/Seoul');
const date = now.toFormat('yyyy-MM-dd');
const time = now.toFormat('HH:mm');

// 음식이 없으면 빈 배열을 돌려서 다음 노드가 실행되지 않게 합니다.
if (!analysis.is_food || !analysis.foods || analysis.foods.length === 0) {
  return [];
}

return analysis.foods.map((food) => ({
  json: {
    date,
    time,
    meal_type: analysis.meal_type,
    food_name: food.food_name,
    amount: food.amount,
    calories: Math.round(food.calories),
    carbs_g: Math.round(food.carbs_g * 10) / 10,
    protein_g: Math.round(food.protein_g * 10) / 10,
    fat_g: Math.round(food.fat_g * 10) / 10,
    sodium_mg: Math.round(food.sodium_mg),
    confidence: food.confidence,
    chat_id: msg.chat.id,
    message_id: msg.message_id,
  },
}));
```

### 1-11. `Code` — 이름: 회신 메시지 작성

Mode는 Run Once for All Items다. 앞 노드가 음식 수만큼 낸 아이템을 메시지 하나로 모은다.

```javascript
// 기록된 행들을 모아 텔레그램 회신 메시지 한 개를 만듭니다.
// (Run Once for All Items 모드: 아이템 N개 -> 메시지 1개)
const rows = $input.all().map((item) => item.json);
const analysis = $('음식 분석').first().json.output;

const sum = (key) => rows.reduce((acc, r) => acc + Number(r[key] || 0), 0);

const lines = rows.map(
  (r) => `- ${r.food_name} (${r.amount}) ${r.calories} kcal${r.confidence === '낮음' ? ' [추정 불확실]' : ''}`
);

const text = [
  `[${rows[0].date} ${rows[0].time} · ${rows[0].meal_type}] 기록 완료`,
  '',
  ...lines,
  '',
  `합계: ${sum('calories')} kcal`,
  `탄수화물 ${Math.round(sum('carbs_g'))} g · 단백질 ${Math.round(sum('protein_g'))} g · 지방 ${Math.round(sum('fat_g'))} g · 나트륨 ${Math.round(sum('sodium_mg'))} mg`,
  '',
  analysis.summary,
].join('\n');

return [{ json: { text, chat_id: rows[0].chat_id } }];
```

## 2. 워크플로우 `02_일일리포트_건강조언`

워크플로우 Settings에서 Timezone이 `Asia/Seoul`인지 확인한다. 실행 환경의 `TIMEZONE`이 `Asia/Seoul`이면 기본값으로 둔다. 이 워크플로우에는 Code 노드가 없다. 여러 행의 합계를 전용 노드(Filter, Edit Fields, Summarize)로 낸다.

**연결 순서**

```text
매일 21시 → 프로필 읽기 → 오늘 기록 읽기 → 빈 행 거르기 → 값 정리 → 오늘 합계 → 집계 결과 → 건강 조언 생성 → 리포트 메일 발송
건강 조언 생성의 Chat Model 연결점 ← OpenAI Chat Model
```

| `fat_g` | Number | `{{ Number($json.fat_g \|\| 0) }}` |
| `sodium_mg` | Number | `{{ Number($json.sodium_mg \|\| 0) }}` |
| `line` | String | `- {{ $json.time }} {{ $json.meal_type }}: {{ $json.food_name }} ({{ $json.amount }}) {{ $json.calories }} kcal` |

영양 성분을 숫자로 바꾸는 이유는 다음 노드의 Sum이 숫자 타입인 값만 더하기 때문이다. 시트가 숫자를 문자열로 돌려주면 그 값이 합계에서 빠진다.

```text
당신은 친절한 임상영양사입니다. 사용자의 하루 식단 기록과 개인 프로필을 보고 오늘의 식습관을 평가하고 내일을 위한 조언을 합니다.

작성 규칙
- 한국어, 합니다체로 씁니다. 텔레그램 메시지이므로 마크다운 기호(#, **, |)를 쓰지 않고 줄바꿈과 "-" 목록만 사용합니다.
- 전체 길이는 600자 이내로 씁니다.
- 구성: (1) 오늘 총평 한두 문장 (2) 목표 대비 잘한 점 1~2개 (3) 개선할 점 1~2개와 구체적인 대안 음식 (4) 내일 한 가지 실천 과제

```
