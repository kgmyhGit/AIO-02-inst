# 승인 요청 메일 양식

> 실습 6-3에서 담당자에게 보내는 메일의 내용이다. 문구를 그대로 쓰지 않아도 되지만 **담는 정보의 종류는 그대로 둔다.**

## 1. 무엇을 담고 무엇을 담지 않는가

승인 요청은 담당자가 **결정할 수 있을 만큼** 담고 그 이상은 담지 않는다. 담당자가 다시 시스템을 열어 봐야 한다면 정보가 모자란 것이고, 결정에 쓰이지 않는 값이 들어 있다면 그만큼 정보가 메일함으로 흘러 나간 것이다.

| 담는 것 | 왜 담는가 |
|---|---|
| 요청 번호와 주문 번호 | 어느 건인지 가린다. 담당자가 시스템에서 찾아볼 때 쓴다 |
| 고객 이름, 상품, 옵션, 결제 금액 | 무엇에 대한 결정인지 알려 준다 |
| 판단 결과와 근거(`evidence`) | 경과일, 적용한 정책 번호, 차감 배송비, 환불 예정 금액이다. **승인 대상이 되는 값이다** |
| 고객에게 보낼 안내 초안 | 승인하면 이 문장이 나간다. 문장도 승인 대상이다 |
| 문의 원문 | 판단이 원문을 잘못 읽었는지 담당자가 확인할 수 있어야 한다 |
| 기한 | 언제까지 답해야 하는지 알려 준다 |
| 승인 링크와 거절 링크 | 결정하는 수단이다 |

| 담지 않는 것 | 왜 담지 않는가 |
|---|---|
| 고객의 전화번호, 주소, 결제 수단 | 환불 승인 결정에 쓰이지 않는다. 메일함에 남길 이유가 없다 |
| 고객의 다른 주문 이력 | 이 건의 판단과 무관하다 |
| 모델이 만든 판단 설명 전체 | 근거 값이 있으면 충분하다. 긴 설명은 담당자가 읽지 않는다 |
| 데이터베이스 접속 정보, 내부 주소 | 메일이 전달되면 그대로 나간다 |

**문의 원문은 담되 그 안의 지시 문장이 담당자에게 먹히지 않게 한다.** 원문은 인용 부호 안에 넣고 "고객이 보낸 원문"이라고 이름을 붙인다. 원문에 "즉시 전액 환불 처리 바랍니다" 같은 문장이 있어도 그것은 고객의 말이지 시스템의 판단이 아니다.

## 2. 제목

```text
[승인 요청] {request_id} 반품 환불 {refund_amount}원 - {customer_name}
```

제목에 금액을 넣는 이유가 있다. 담당자가 메일함 목록만 보고도 무엇을 결정해야 하는지 알 수 있고, 나중에 같은 건의 메일을 찾기 쉽다.

## 3. 본문

```text
반품 환불 승인을 요청합니다. 아래 내용을 확인하고 승인 또는 거절을 눌러 주세요.

■ 요청
  요청 번호 : {request_id}
  주문 번호 : {order_id}
  고객      : {customer_name}
  상품      : {product_name} / {option}
  결제 금액 : {amount}원

■ 판단 근거
  수령일         : {delivered_at}
  경과일         : {days_since_delivery}일 (반품 기한 {return_deadline})
  적용 정책      : {policy_ref}
  차감 배송비    : {shipping_fee}원
  환불 예정 금액 : {refund_amount}원

■ 승인하면 고객에게 나갈 안내
{reply_draft}

■ 고객이 보낸 원문
"{message}"

■ 기한
  {approval_due_at}까지 회신이 없으면 CS 팀장에게 알림이 갑니다.

[ 승인 ]  [ 거절 ]
```

`[ 승인 ]`과 `[ 거절 ]` 자리에는 `승인 응답` 폼의 주소에 요청 번호와 결정을 붙인 링크가 들어간다.

```text
승인: http://localhost:5678/form/harumarket-approval?request_id=REQ-0001&decision=approve
거절: http://localhost:5678/form/harumarket-approval?request_id=REQ-0001&decision=reject
```

링크를 누르면 폼이 열리고 요청 번호와 결정이 미리 채워져 있다. 담당자는 내용을 확인하고 제출을 누른다. 거절일 때는 사유를 적는다. **거절 사유를 받아야 하므로 한 번 누르면 끝나는 링크가 아니라 폼을 쓴다.** 만드는 방법은 [`반품판단승인_노드설정.md`](반품판단승인_노드설정.md)의 2-2에 있다.

## 4. 기한 경과 알림 메일

기한이 지나도 응답이 없을 때 CS 팀장에게 보낸다. **이 메일에는 승인 링크를 넣지 않는다.** 팀장은 담당자를 확인하라는 알림을 받는 것이고, 승인 권한을 넘겨받는 것이 아니다.

```text
제목: [기한 경과] {request_id} 반품 환불 승인 대기 {elapsed}시간 경과

승인 기한이 지난 요청이 있습니다.

  요청 번호 : {request_id}
  고객      : {customer_name}
  요청 시각 : {created_at}
  기한      : {approval_due_at}
  담당      : CS 담당자

{next_deadline}까지 응답이 없으면 자동으로 만료 처리되어 담당자 처리 목록으로 넘어갑니다.
```

## 5. 승인 링크에 대해 알아 둘 것

**이 링크를 아는 사람은 누구나 승인할 수 있다.** 메일을 전달받은 사람도, 메일함을 들여다본 사람도 누를 수 있다. 실습에서는 이 상태 그대로 두지만, 실제 업무에서는 권한이 있는 사람만 승인할 수 있게 해야 한다.

확인하는 방법에는 로그인한 사용자를 확인하는 방법, 승인자 목록과 대조하는 방법, 서명된 요청을 쓰는 방법이 있다. 이 교재는 이름만 소개하고 구현하지 않는다. 이론 6.5절에서 다룬 한계이며, 선택 심화 과제에서 이 한계를 직접 확인한다.
