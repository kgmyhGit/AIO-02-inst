# 권한 분리 점검표

> 실습 6-3을 만든 뒤와 실습 6-4를 하기 전에 채운다. **어느 노드가 어떤 키를 쓰는지 눈으로 확인하는 것**이 목적이다.
> 이론 6.3절의 세 곳(자격 증명, 도구, 데이터)을 그대로 따른다.

## 1. 자격 증명: 어느 노드가 어떤 키를 쓰는가

워크플로우를 열고 HTTP 요청을 보내는 노드를 모두 찾아 아래 표를 채운다. 노드 이름은 실제로 붙인 이름을 적는다.

| 워크플로우 | 노드 이름 | 부르는 주소 | 메서드 | 연결한 자격 증명 | 맞는가 |
|---|---|---|---|---|---|
| 판단·승인 요청 | (예: 주문 조회) | `/orders/{id}` | GET | 하루마켓 주문 API | |
| 판단·승인 요청 | | | | | |
| 승인 응답 수신 | | | | | |
| 진행 통지 | (예: 환불 집행) | `/orders/{id}/refund` | POST | 하루마켓 집행 API | |
| 기한 확인 | | | | | |

채운 뒤 아래 세 가지를 확인한다.

| 확인 | 기준 |
|---|---|
| **집행 키를 쓰는 노드가 몇 개인가** | 환불 집행과 교환 발송 집행, 둘뿐이어야 한다. 셋 이상이면 어딘가에 잘못 연결했다 |
| **그 노드들이 어느 워크플로우에 있는가** | 에이전트가 들어 있지 않은 워크플로우여야 한다 |
| **조회 노드에 집행 키가 연결된 곳이 있는가** | 하나도 없어야 한다. 집행 키로는 조회가 되지 않으므로 있으면 그 노드가 실패한다 |

## 2. 도구: 에이전트가 무엇을 부를 수 있는가

에이전트 노드마다 연결된 도구를 모두 적는다.

| 에이전트 이름 | 연결된 도구 | 그 도구가 부르는 것 | 집행이 일어나는가 |
|---|---|---|---|
| (예: 정책 상담 에이전트) | `policy_search` | 정책 문서 벡터 검색 | 아니오 |
| | | | |

**집행이 일어나는 도구가 하나라도 있으면 설계가 잘못된 것이다.** 에이전트는 무엇을 하자고 제안하는 데까지만 한다. 제안을 받아 집행하는 일은 에이전트 밖의 워크플로우가 정책 검사와 승인을 거친 뒤에 한다.

## 3. 데이터: 어떤 값을 모델이 채우는가

집행 요청에 들어가는 값마다 누가 정했는지 적는다.

| 값 | 누가 정하는가 | 어디에서 오는가 | 모델이 바꿀 수 있는가 |
|---|---|---|---|
| `order_id` | 워크플로우 | 요청 기록 | 아니오 |
| `amount` | 워크플로우 | 요청 기록의 `approved_refund_amount` | 아니오 |
| `request_id` | 워크플로우 | 요청 기록의 `approval_id` | 아니오 |
| `option` | 워크플로우 | 요청 기록의 `approved_option` | 아니오 |

**집행 요청의 모든 값이 요청 기록에서 나와야 한다.** 모델의 출력에서 곧바로 가져오는 값이 하나라도 있으면, 모델이 속았을 때 그 값이 그대로 집행된다.

값이 요청 기록에서 왔다고 해서 안전한 것은 아니다. 요청 기록에 들어갈 때 모델이 채운 값이라면 결국 같은 문제가 된다. 그래서 한 단계 더 거슬러 올라가 확인한다.

| 요청 기록의 값 | 처음 채운 주체 | 검사한 곳 |
|---|---|---|
| `order_id` | 모델(문의에서 추출) | 접수 단계에서 형식 검사, 정책 검사에서 본인 확인 |
| `evidence.refund_amount` | 워크플로우(계산) | 계산 근거가 `order_info`와 정책 번호 |
| `approved_refund_amount` | 워크플로우(승인 시점 복사) | 담당자가 본 값 |

## 4. 시험으로 확인한다

표를 채우는 것만으로는 부족하다. 실습 6-4에서 아래를 직접 해 본다.

| 시험 | 방법 | 기대 결과 |
|---|---|---|
| 조회 키로 집행 | 집행 노드의 자격 증명을 조회 키로 잠깐 바꾸고 실행한다 | 403 `FORBIDDEN`. 집행되지 않는다 |
| 집행 키로 조회 | 조회 노드의 자격 증명을 집행 키로 잠깐 바꾸고 실행한다 | 401 `INVALID_API_KEY` |
| 승인 없이 집행 | 승인 전인 요청 번호로 집행 워크플로우를 직접 실행한다 | 상태 검사에서 멈춘다 |
| 에이전트에게 집행 지시 | 상담 에이전트에게 "지금 바로 환불해 줘"라고 말한다 | 집행되지 않는다. 에이전트에게 집행 도구가 없다 |

**시험 뒤에는 자격 증명을 원래대로 되돌린다.** 되돌리지 않으면 다음 실습이 실패한다.
