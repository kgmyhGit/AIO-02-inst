# 웹 문의 요청 보내는 방법

> 3장 실습 3-6에서 `Webhook` 노드에 시험 요청을 보낼 때 사용한다.

실습 3-6에서는 웹 문의 양식이 보내는 것과 같은 요청을 직접 만들어 보낸다. 요청 본문은 [`웹문의_요청샘플.json`](../data/웹문의_요청샘플.json)에 6건이 들어 있다.

## 1. 보낼 주소 확인하기

n8n 편집 화면에서 `Webhook` 노드를 열면 두 개의 주소가 보인다.

| 주소 | 언제 쓰는가 | 결과를 보는 곳 |
|---|---|---|
| **Test URL** | 편집 중에 시험할 때. 노드에서 **Listen for test event**를 누른 뒤 요청을 보내야 받는다 | 편집 화면의 노드 출력 패널 |
| **Production URL** | 워크플로우를 **Publish**한 뒤 실제로 받을 때 | 왼쪽 메뉴의 실행 목록 |

실습 3-6의 6단계까지는 Test URL을 쓴다. Test URL은 **Listen for test event**를 누른 뒤 한 번의 요청만 받는다. 다음 요청을 보내려면 다시 누른다.

두 주소는 모두 `.env`의 `N8N_WEBHOOK_URL`에 적은 공개 주소로 시작한다. 요청이 ngrok을 거쳐 들어오므로 요청을 보낼 때 `ngrok http 5678`이 실행 중이어야 한다.

## 2. 본문을 파일로 저장하기

요청 본문을 명령줄에 직접 적으면 따옴표와 한글 때문에 실수하기 쉽다. 본문을 파일로 저장한 뒤 그 파일을 보내는 편이 확실하다.

작업 폴더에 `W-1.json` 파일을 만들고 `웹문의_요청샘플.json`의 `W-1` 항목에 있는 `body` 부분만 복사해 넣는다. **파일은 UTF-8로 저장한다.** 예를 들어 `W-1.json`의 내용은 다음과 같다.

```json
{
  "name": "최민지",
  "order_no": "O-1004",
  "content": "셔츠 사이즈가 생각보다 커서 반품하고 싶어요. 입어 보지는 않았고 택도 그대로 있어요.",
  "agree_privacy": true
}
```

나머지 5건도 같은 방식으로 `W-2.json`부터 `W-6.json`까지 만든다.

## 3. 요청 보내기

아래 명령에서 `<TEST_URL>`을 1번에서 확인한 주소로 바꾼다.

### Windows(PowerShell), macOS, Linux 공통

`curl.exe`는 Windows 10 이상과 최근 macOS·Linux에 기본으로 들어 있다. PowerShell에서는 `curl`이 아니라 **`curl.exe`라고 정확히 적어야 한다.** PowerShell의 `curl`은 다른 명령의 별칭이라 아래 옵션이 통하지 않는다.

```bash
curl -X POST -H "Content-Type: application/json; charset=utf-8" --data-binary "@W-1.json" "<TEST_URL>"
```

### PowerShell만 쓰고 싶을 때

```bash
Invoke-RestMethod -Method Post -Uri "<TEST_URL>" -ContentType "application/json; charset=utf-8" -InFile "W-1.json"
```

### 확인

요청을 보낸 뒤 n8n 편집 화면으로 돌아가면 `Webhook` 노드의 출력 패널에 받은 데이터가 나타난다. 본문은 `body` 아래에 들어 있다.

## 4. 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `404` 응답이 온다 | **Listen for test event**를 누르지 않았거나, 한 번 받은 뒤 다시 누르지 않았다 | 노드에서 다시 누르고 요청을 보낸다 |
| 한글이 깨져서 들어온다 | 파일이 UTF-8이 아니거나 `charset=utf-8`을 빼먹었다 | 편집기에서 인코딩을 UTF-8로 저장하고 명령의 `Content-Type`을 확인한다 |
| PowerShell에서 옵션 오류가 난다 | `curl`이 `Invoke-WebRequest`의 별칭으로 동작했다 | `curl.exe`로 적거나 `Invoke-RestMethod`를 쓴다 |
| 연결이 거부된다 | 컨테이너가 떠 있지 않거나 포트를 바꿔 실행했다 | `docker compose ps`로 상태를 보고, 주소의 포트 번호를 확인한다 |
| ngrok의 오류 메시지가 돌아온다 | 터널이 닫혀 있거나 n8n이 실행 중이 아니다 | `ngrok http 5678`과 `docker compose ps`를 확인한다 |
| 응답으로 ngrok 경고 페이지의 HTML이 돌아온다 | 무료 플랜의 경고 페이지가 요청에 적용되었다 | 명령에 `-H "ngrok-skip-browser-warning: true"`를 더한다 |
| 본문이 `body`가 아니라 문자열 하나로 들어온다 | `Content-Type`을 지정하지 않아 JSON으로 해석되지 않았다 | 명령의 `-H` 또는 `-ContentType` 부분을 확인한다 |
