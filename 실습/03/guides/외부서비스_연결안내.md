# 외부 서비스 연결 안내

> 3장 실습 3-3(주식 뉴스 RSS 메일 받기)과 실습 3-5(Daum 경제 뉴스 수집과 저장)에서 쓴다. 화면 이름은 2026년 11월 기준이다. Google Cloud와 Discord의 화면은 자주 바뀌므로, 이름이 다르면 같은 뜻의 메뉴를 찾는다.

## 1. RSS 피드

RSS는 웹사이트가 새 글 목록을 정해진 XML 형식으로 공개하는 방식이다. 사이트가 목록 파일(피드)을 고정된 주소에 올려 두면, 프로그램은 그 주소를 읽어 새 글이 있는지 확인한다. 사람이 사이트를 방문하지 않아도 새 글을 받아 볼 수 있다.

피드에는 글마다 항목이 하나씩 있고, 항목에는 보통 다음 값이 들어 있다.

| 값 | 뜻 |
|---|---|
| 제목(`title`) | 글 제목 |
| 주소(`link`) | 글 원문으로 가는 주소 |
| 발행 시각(`pubDate`) | 글을 올린 시각 |
| 요약(`description`) | 요약이나 본문 일부 |
| 식별자(`guid`) | 글마다 다른 값 |

피드의 형식은 RSS 2.0, RSS 1.0, Atom처럼 여러 가지이고, 같은 형식이어도 사이트마다 넣는 값이 다르다. 발행 시각이 없는 피드도 있다. n8n의 `RSS Read` 노드는 여러 형식을 읽어 `title`, `link`, `pubDate`, `isoDate`, `content`, `contentSnippet`, `guid` 같은 공통 필드로 바꾸어 준다. 다만 피드에 원래 없는 값은 만들어 주지 않는다. 그래서 새 피드를 쓸 때는 먼저 한 번 실행해 어떤 필드가 오는지 확인한다.

RSS는 인증 키가 필요 없고 조회만 할 수 있다. 검색어나 필터를 지정할 수 없는 피드가 많아서, 원하는 글만 고르려면 받은 뒤에 워크플로우가 걸러야 한다. Google 뉴스는 검색어를 주소에 넣은 검색 피드를 제공한다.

```text
https://news.google.com/rss/search?q=<검색어>&hl=ko&gl=KR&ceid=KR:ko
```

`<검색어>`가 한글이면 주소에 넣을 수 있는 형식으로 바꾸어 적는다. `주식`은 `%EC%A3%BC%EC%8B%9D`다. 브라우저 주소창에 한글로 넣고 복사하면 바뀐 값이 복사된다.

## 2. Gmail 자격 증명(실습 3-3)

n8n의 Gmail 노드는 OAuth2 방식으로 Google에 연결한다. n8n이 Google에 "이 사용자의 메일을 보내도 되는가"를 묻고, 사용자가 Google 로그인 화면에서 허락하면 Google이 n8n에 출입증(토큰)을 준다. n8n에는 Google 비밀번호가 저장되지 않는다.

n8n이 이 요청을 하려면 Google Cloud에 등록된 앱이 있어야 한다. 그 앱의 클라이언트 ID와 클라이언트 보안 비밀번호(Client Secret)를 n8n 자격 증명에 넣는다.

**필요한 것:** Google 계정. Google Cloud 프로젝트를 만들고 Gmail API를 쓰는 데 결제 수단은 필요하지 않다.

### 2.1 Google Cloud에서 준비하기

1. `https://console.cloud.google.com`에 Google 계정으로 로그인하고 새 프로젝트를 만든다. 이름은 `n8n 실습`처럼 알아보기 쉽게 붙인다.
2. 화면 위쪽에서 만든 프로젝트가 선택되어 있는지 확인한다.
3. API 및 서비스 › 라이브러리에서 `Gmail API`를 찾아 사용 설정한다.
4. OAuth 동의 화면(Google 인증 플랫폼)을 연다.
    - 앱 이름과 사용자 지원 이메일을 넣는다.
    - 대상(사용자 유형)은 외부(External)를 고른다.
    - 테스트 사용자(대상 › Test users)에 메일을 받을 본인 Google 계정을 추가한다. 여기에 없는 계정은 로그인할 수 없다.
5. 사용자 인증 정보(클라이언트) › 사용자 인증 정보 만들기 › OAuth 클라이언트 ID를 고른다.
    - 애플리케이션 유형: 웹 애플리케이션
    - 승인된 리디렉션 URI: 아래 2.2의 1번에서 n8n이 보여 주는 OAuth Redirect URL을 붙여 넣는다.
6. 만들어진 클라이언트 ID와 클라이언트 보안 비밀번호를 복사해 둔다. 보안 비밀번호는 다른 사람에게 보이지 않게 한다.

### 2.2 n8n에서 자격 증명 만들기

1. `Gmail` 노드의 Credential to connect with에서 새 자격 증명을 만든다. 유형은 Gmail OAuth2 API다. 창 위쪽의 OAuth Redirect URL을 복사해 2.1의 5번에 넣는다.
2. Client ID와 Client Secret 칸에 2.1의 6번 값을 넣는다.
3. 자격 증명 이름을 `Gmail 실습`으로 붙이고 Sign in with Google을 누른다.
4. Google 로그인 창에서 테스트 사용자로 넣은 계정을 고른다. "Google에서 확인하지 않은 앱"이라는 경고가 나오면 고급 › 이동을 눌러 계속한다. 본인이 만든 앱에 본인 계정으로 들어가는 것이다.
5. 권한을 허용하면 n8n 창에 연결되었다는 표시가 나온다.

OAuth Redirect URL이 ngrok 공개 주소로 시작하면 로그인할 때 ngrok이 실행 중이어야 한다. Google이 로그인을 마친 뒤 그 주소로 돌아오기 때문이다.

### 2.3 자주 만나는 오류

| 증상 | 확인할 위치 | 수정 방법 |
|---|---|---|
| Google 창에 `400 오류: redirect_uri_mismatch` | Google Cloud의 승인된 리디렉션 URI | n8n 자격 증명 창의 OAuth Redirect URL을 복사해 다시 붙여 넣는다. 끝의 `/`까지 같아야 한다 |
| Google 창에 `403 오류: access_denied` | OAuth 동의 화면의 테스트 사용자 | 로그인한 계정을 테스트 사용자에 추가한다 |
| 며칠 뒤 `메일 보내기`가 인증 오류로 멈춘다 | 실행 기록의 오류 메시지 | 테스트 상태의 앱은 Google이 정한 기간이 지나면 로그인이 풀린다. 자격 증명 창에서 다시 로그인한다 |
| `Gmail API has not been used in project` | Google Cloud의 API 라이브러리 | 2.1의 3번을 같은 프로젝트에서 했는지 확인한다 |

## 3. Discord 웹후크(실습 3-5)

웹후크는 정해진 주소로 요청을 보내면 그 내용이 Discord 채널에 메시지로 올라가게 하는 기능이다. 봇을 만들지 않아도 채널에 메시지를 보낼 수 있다.

**필요한 것:** Discord 계정과, 웹후크를 만들 권한이 있는 서버. 본인이 만든 서버이면 권한이 있다. 비용은 들지 않는다.

1. Discord에서 서버를 하나 만든다(서버 목록의 `+` › 직접 만들기). 이미 있는 실습용 서버를 써도 된다.
2. 알림을 받을 채널의 설정(톱니바퀴) › 연동 › 웹후크 › 새 웹후크를 누른다.
3. 웹후크 이름을 `n8n 뉴스 알림`처럼 붙이고 웹후크 URL 복사를 누른다.
4. n8n의 `Discord` 노드에서 Connection Type을 Webhook으로 두고, 새 자격 증명(유형 Discord Webhook)의 Webhook URL 칸에 복사한 주소를 넣는다. 자격 증명 이름은 `Discord 실습 채널`로 붙인다.

**웹후크 주소는 비밀번호처럼 다룬다.** 주소를 아는 사람은 누구나 그 채널에 메시지를 보낼 수 있다. 노드 칸에 직접 적지 않고 자격 증명에 두며, 주소가 밖으로 나갔다면 Discord에서 그 웹후크를 지우고 새로 만든다.

| 증상 | 확인할 위치 | 수정 방법 |
|---|---|---|
| `Discord 알림`이 404 오류로 멈춘다 | Discord 채널의 웹후크 목록 | 웹후크가 지워졌다. 새로 만들어 자격 증명의 주소를 바꾼다 |
| 메시지가 다른 채널에 올라간다 | 웹후크 설정의 채널 | 웹후크마다 채널이 정해져 있다. 웹후크 설정에서 채널을 바꾼다 |
