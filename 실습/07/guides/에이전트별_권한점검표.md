# 에이전트별 권한 점검표

> 6장 [`권한분리_점검표.md`](../../../06/템플릿_가이드/guides/권한분리_점검표.md)를 역할 단위로 넓힌 것이다. 역할이 여럿이 되면 어느 역할이 어떤 도구와 자격 증명을 쓰는지 한눈에 보기 어려우므로, 만들 때마다 이 표를 채운다.
> 7장 이론 7.9절 표 7-26이 채운 예다.

## 채우는 방법

- 역할(에이전트와 모델 호출 단계)과 워크플로우를 **모두** 한 줄씩 적는다. 감독 에이전트도 한 줄이다.
- **도구** 칸에는 그 역할에 연결된 도구를 모두 적는다. 하위 에이전트(`AI Agent Tool`)나 역할 서브워크플로우를 도구로 쓰면, 그 안의 도구도 괄호로 함께 적는다.
- **자격 증명** 칸에는 그 역할이 쓰는 도구 안의 자격 증명까지 적는다. 조회 키와 집행 키를 구분한다.
- **바꿀 수 있는 것** 칸에는 그 역할이 실행되어 바뀔 수 있는 외부의 값을 적는다. 모델 호출은 바꾸는 것이 아니다.

## 확인 질문

| 질문 | 답 |
|---|---|
| 에이전트, 모델 호출, 감독 줄의 "바꿀 수 있는 것" 칸이 모두 "없다"인가? | |
| 집행 키(`하루마켓 집행 API`)를 쓰는 줄이 워크플로우 줄뿐인가? | |
| 감독 에이전트의 도구 안에(하위 에이전트나 서브워크플로우 안까지) 상태를 바꾸는 도구가 없는가? | |
| 승인을 요청하는 노드가 워크플로우 줄에만 있는가? | |
| 대상을 정하는 값(요청 번호, 고객 이름, 주문번호)을 모델이 채우는 도구 입력이 있는가? 있다면 이유는? | |

**첫째 질문의 답이 "아니다"이면 설계를 다시 본다.** 에이전트가 늘어도 집행 권한을 가진 주체는 늘지 않아야 한다.
