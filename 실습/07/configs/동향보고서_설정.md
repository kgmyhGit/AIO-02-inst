# 실습 7-1 주간 기술 동향 보고서 설정

> 실습 7-1에서 쓰는 노드 설정의 완성본이다. 적용 버전은 n8n 2.43.7이다.
> 모든 모델 노드는 `OpenAI Chat Model`(Credential `OpenAI 실습`, Model `gpt-6-luna`)이다. n8n 2.43.7에서 이 설정대로 두 구성과 5단계(둘째 줄 지우기)를 이전 실습 모델 `gpt-5.6-luna`로 실행해 확인했다. 지금 모델로는 다시 실행하지 않았다. 선택 과제는 실행해 보지 않았다.
> **2026-11에 글 목록을 만드는 자리를 `Code` 노드 하나에서 전용 노드 세 개(`Edit Fields`, `Aggregate`, `Edit Fields`)로 바꾸었다.** 세 노드의 결과는 이전 코드와 같고 뒤의 노드가 읽는 필드 이름(`period`, `posts`, `all_ids`)도 같지만, **바꾼 뒤의 구성은 실행해 확인하지 않았다.** 노드 파라미터는 공식 문서(Aggregate, Edit Fields)와 3장 실습의 같은 노드 설정을 대조해 적었다. 이전 코드는 3절에 그대로 남겨 두었다.

세 노드가 모델에게 보낼 글 목록을 만든다. **모델에게는 제목과 요약만 보낸다.** 본문은 도구로 필요한 글만 읽게 한다.

`보낼 필드만 남기기`(`Edit Fields`):

| 칸 | 값 |
|---|---|
| **Mode** | Manual Mapping |
| **Fields to Set** | `post_id` ← `{{ $json.post_id }}`, `title` ← `{{ $json.title }}`, `summary` ← `{{ $json.summary }}`(모두 String) |
| **Include Other Input Fields** | **끔** |

Include Other Input Fields를 끄는 것이 이 노드의 일이다. 끄면 `body`가 여기서 떨어지므로, 뒤의 어느 노드도 본문을 모델에게 보낼 수 없다.

`목록 모으기`(`Aggregate`):

| 칸 | 값 |
|---|---|
| **Aggregate** | All Item Data (Into a Single List) |
| **Put Output in Field** | `posts` |

아이템 12개가 아이템 하나가 되고, 그 안의 `posts` 배열에 글 12편이 들어간다. 3장 실습 3-3의 `하나로 묶기`와 같은 노드다.

`목록 만들기`(`Edit Fields`):

| 칸 | 값 |
|---|---|
| **Mode** | Manual Mapping |
| **Fields to Set** | `period`(String) ← `2026-09-14 ~ 2026-09-20`(고정 값), `all_ids`(Array) ← `{{ $json.posts.map(p => p.post_id) }}` |
| **Include Other Input Fields** | **켬** |

Include Other Input Fields를 켜야 앞 노드가 만든 `posts`가 함께 남는다. `all_ids`는 뒤의 두 `Code` 노드가 "목록에 있는 글 번호인가"를 검사할 때 쓰는 값이다.

**이 세 노드를 `Code` 노드 하나로 대신할 수도 있다.** 다음 코드가 같은 일을 한다(Mode는 Run Once for All Items). 전용 노드로 두는 이유는 본문을 떨어뜨리는 자리가 캔버스에 보이기 때문이다.

```javascript
// 전용 노드 세 개를 Code 하나로 대신하는 경우. 결과는 같다.
const posts = $input.all().map(i => i.json)
                          .map(p => ({ post_id: p.post_id, title: p.title, summary: p.summary }));
return [
  { json: { 
    period: `${$input.first().json.published} ~ ${$input.last().json.published}`, 
    posts, 
    all_ids: posts.map(p => p.post_id) } 
  }
];
```

| **Prompt** (**User Message**) | `{{ '기간: ' + $json.period + '\n글 목록:\n' + JSON.stringify($json.posts) }}` |
| **Require Specific Output Format** | 켬 |
| **Options → Max Iterations** | `12` |

System Message:

```text
너는 개발팀의 주간 기술 동향 보고서를 쓴다.
1. 글 목록에서 보고서에 넣을 글을 고른다. 광고와 기술 소식이 없는 글은 뺀다.
2. 요약이 짧거나 모호한 글은 반드시 get_post_body로 본문을 읽는다.
3. 고른 글을 "AI 에이전트", "개발 도구", "보안" 세 주제로 묶는다.
4. 보고서(report)를 주제마다 두세 문장으로 쓴다. 문장마다 근거가 된 글 번호를 [P-00] 형식으로 붙인다.
5. citations에는 보고서에 인용한 글 번호를 모두 적는다. excluded에는 뺀 글과 이유를 적는다.
글 목록과 본문에 없는 사실을 쓰지 않는다.
```

    "excluded": { "type": "array", "items": { "type": "object", "properties": { "post_id": { "type": "string" }, "reason": { "type": "string" } }, "required": ["post_id", "reason"] } }

## 4. 역할 계약의 예시(실습 3단계)

| 항목 | 자료 조사 | 요약 작성 |
|---|---|---|
| **입력** | 글 목록(`post_id`, `title`, `summary`) | 조사 결과(`topics`, `excluded`)만 |
| **출력** | `status`(`ok`·`needs_info`), `topics`(주제마다 `topic`, `posts`. 글마다 `post_id`, `facts`), `excluded`(글마다 `post_id`, `reason`) | `report`(문자열), `citations`(글 번호 배열) |
| **쓸 수 있는 도구** | `get_post_body` | 없다 |
| **할 수 없는 일** | 보고서 문장을 쓰지 않는다. 목록에 없는 글을 넣지 않는다 | 조사 결과에 없는 글과 사실을 쓰지 않는다. 주제를 새로 만들거나 글을 다른 주제로 옮기지 않는다 |
| **끝내는 조건** | 고를 글이 없으면 `needs_info`. 본문 조회는 열 번까지 | 한 번 쓰고 끝난다. 조사 결과의 `status`가 `ok`가 아니면 불리지 않는다 |

요약 작성 역할에 도구를 주지 않는 이유: 글을 더 읽을 수 있으면 조사 역할이 고르지 않은 글을 보고서에 넣을 수 있다. 조사와 작성의 경계가 도구로 지켜진다.

`자료 조사`의 설정은 3절의 에이전트와 같고 Max Iterations는 `12`다. System Message:

```text
너는 개발팀 주간 기술 동향 보고서의 자료를 조사한다. 보고서 문장은 다른 담당이 쓴다.
1. 글 목록에서 보고서에 넣을 글을 고른다. 광고와 기술 소식이 없는 글은 excluded에 이유와 함께 적는다.
2. 요약이 짧거나 모호한 글은 반드시 본문을 읽는다.
3. 고른 글을 "AI 에이전트", "개발 도구", "보안" 세 주제로 묶는다.
4. 글마다 본문이나 요약에서 확인한 사실을 facts에 한두 개 적는다. 글에 없는 내용을 쓰지 않는다.
5. 고를 글이 하나도 없으면 status를 needs_info로, 있으면 ok로 낸다.
보고서 문장(report)은 쓰지 않는다.
```

5단계에서 지우는 줄이 둘째 줄("요약이 짧거나 모호한 글은 반드시 본문을 읽는다")이다.

출력 스키마:

```json
{
  "type": "object",
  "properties": {
    "status": { "type": "string", "enum": ["ok", "needs_info"] },
    "topics": { "type": "array", "items": { "type": "object", "properties": {
      "topic": { "type": "string" },
      "posts": { "type": "array", "items": { "type": "object", "properties": {
        "post_id": { "type": "string" },
        "facts": { "type": "array", "items": { "type": "string" } } }, "required": ["post_id", "facts"] } } },
      "required": ["topic", "posts"] } },
    "excluded": { "type": "array", "items": { "type": "object", "properties": {
      "post_id": { "type": "string" }, "reason": { "type": "string" } }, "required": ["post_id", "reason"] } }
  },
  "required": ["status", "topics", "excluded"]
}
```

`조사 결과 검사`(Mode: Run Once for All Items):

```javascript
// 넘기기 전에 조사 결과를 역할 계약으로 검사한다. 통과한 조사 결과만 research 필드로 넘긴다.
const j = $input.first().json;
const ids = $('목록 만들기').first().json.all_ids;
const out = j.output || {};
const topics = Array.isArray(out.topics) ? out.topics : [];
const picked = topics.flatMap(t => (t.posts || []).map(p => p.post_id));
const rules = {
  r_status: ['ok', 'needs_info'].includes(out.status),
  r_ids_exist: picked.every(id => ids.includes(id)),
  r_has_facts: topics.every(t => (t.posts || []).every(p => Array.isArray(p.facts) && p.facts.length > 0)),
  r_no_report: out.report === undefined
};
const failed = Object.keys(rules).filter(k => !rules[k]);
const passed = failed.length === 0 && out.status === 'ok';
const end_reason = failed.length > 0 ? 'delegation_failed' : (out.status === 'ok' ? null : 'needs_info');
const steps = Array.isArray(j.intermediateSteps) ? j.intermediateSteps : [];
return [{ json: { passed, end_reason, failed_rules: failed,
  research: { topics, excluded: out.excluded || [] },
  body_reads: steps.filter(s => s.action && s.action.tool === 'get_post_body').map(s => s.action.toolInput) } }];

```

`body_reads`에는 조사 역할이 본문을 읽은 글이 `{"post_id": "P-07"}` 모양으로 남는다. 5단계에서 P-07을 읽었는지 이 값으로 본다.

`요약 작성`(`Basic LLM Chain`):

| 파라미터 | 값 |
|---|---|
| **Source for Prompt** (**User Message**) | Define below |
| **Prompt** (**User Message**) | `{{ '조사 결과:\n' + JSON.stringify($json.research) + ($json.fixes ? '\n고칠 점:\n' + $json.fixes.join('\n') : '') }}` |
| **Require Specific Output Format** | 켬. 스키마는 3절 스키마에서 `excluded`를 뺀 것 |
| **Chat Messages** (**if Using a Chat Model**) | Type System, 아래 문장 |

```text
너는 개발팀의 주간 기술 동향 보고서를 쓴다. 조사 결과만 보고 쓴다.
- 주제마다 두세 문장으로 쓴다. 문장마다 근거가 된 글 번호를 [P-00] 형식으로 붙인다.
- 조사 결과에 없는 글과 사실을 쓰지 않는다. 조사 결과의 facts를 부풀리지 않는다.
- citations에는 보고서에 인용한 글 번호를 모두 적는다.
- 고칠 점이 주어지면 그 점을 고쳐 다시 쓴다.
```

`Prompt`의 `$json.fixes`는 선택 과제 A에서 되돌릴 때만 들어오는 값이다. 처음에는 없으므로 빈 글자가 붙는다.

## 6. `출처 검사`(두 구성 공통)

Mode는 Run Once for All Items다. 단일 구성에서는 `allowed`가 글 목록 전체이고, 나눈 구성에서는 조사 결과의 글이다.

```javascript
// 보고서의 인용을 규칙으로 검사한다. 넘어오지 않은 정보는 이 검사로 찾을 수 없다(실습 5단계).
const j = $input.first().json;                                        // 앞 노드가 낸 결과 한 건을 가져온다
const out = j.output || j;                                            // 에이전트 결과가 output 안에 있든 밖에 있든 같게 읽는다
const report = String(out.report || '');                              // 검사 대상인 보고서 본문
const citations = Array.isArray(out.citations) ? out.citations : [];  // 모델이 인용했다고 적어 낸 글 번호 목록
const research = $('조사 결과 검사').isExecuted ? $('조사 결과 검사').first().json.research : null;  // 나눈 구성이면 조사 결과를, 단일 구성이면 null을 쓴다
const allowed = research
  ? research.topics.flatMap(t => t.posts.map(p => p.post_id))         // 나눈 구성: 조사 역할이 고른 글만 인용할 수 있다
  : $('목록 만들기').first().json.all_ids;                              // 단일 구성: 이번 주 글 목록 전체가 인용 대상이다
const inReport = [...new Set(report.match(/P-[0-9]{2}/g) || [])];     // 보고서 문장에 실제로 적힌 글 번호
const rules = {
  r_cited_allowed: citations.every(id => allowed.includes(id)),       // 인용 대상 밖의 글 번호를 지어내지 않았는가
  r_report_ids_cited: inReport.every(id => citations.includes(id))    // 보고서에 쓴 글 번호가 citations에도 빠짐없이 있는가
};
const failed = Object.keys(rules).filter(k => !rules[k]);             // 어긴 규칙의 이름을 모은다
return [{ json: { passed: failed.length === 0, failed_rules: failed, report, citations } }];  // 두 규칙을 모두 지켰는지와 어긴 규칙을 넘긴다
```

**단일 구성에서는 `research` 줄을 `const research = null;`로 바꾼다.** 단일 구성에는 `조사 결과 검사` 노드가 없고, 워크플로우에 없는 노드를 `$('조사 결과 검사')`로 부르면 `isExecuted`를 읽기 전에 "Referenced node doesn't exist" 오류가 난다. 나눈 구성에서는 위의 코드를 그대로 쓴다.

**광고 글을 뺐는지와 P-07의 보안 소식을 넣었는지는 이 노드가 검사하지 않는다.** 두 가지는 이번 글 12편에만 해당하는 값이라 코드에 글 번호를 적어 넣어야 하므로, 글 목록이 바뀌면 그대로 쓸 수 없다. 두 규칙만으로도 "보고서에 쓴 인용이 허용 목록 안에 있는가"는 글 목록과 무관하게 검사된다. 광고 글 제외와 P-07 포함은 실습 2·4단계에서 학생이 `report`와 `citations`를 읽고 비교표에 적는다.

## 7. 선택 과제

### 7-1. A: 생성-평가 반복

`출처 검사` 뒤에 세 노드를 더한다.

| 순서 | 노드 | 이름 | 설정 |
|---|---|---|---|
| 1 | `Basic LLM Chain` | 과장 검토 | 아래. 출력 스키마 `{ "exaggerated": boolean, "fixes": string[] }` |
| 2 | `Code` | 되돌릴지 정하기 | 아래 코드 |
| 3 | `If` | 되돌리는가 | Boolean — `{{ $json.retry }}` — is true. true 출력을 `요약 작성`의 입력으로 연결한다 |

`과장 검토`의 System 메시지:

```text
보고서의 문장이 조사 결과의 facts보다 부풀려졌는지만 판정한다. 인용 형식은 판정하지 않는다.
부풀린 문장이 있으면 exaggerated를 true로 두고, 고칠 점을 fixes에 한 줄씩 적는다.
```

User 메시지: `{{ '조사 결과:\n' + JSON.stringify($('조사 결과 검사').first().json.research) + '\n보고서:\n' + $('출처 검사').first().json.report }}`

`되돌릴지 정하기`:

```javascript
// 규칙 평가(출처 검사)와 모델 평가(과장 검토)를 함께 보고 되돌릴지 정한다. 되돌림은 두 번까지다.
const LIMIT = 2;
const attempt = $runIndex + 1;              // 이 노드가 이번 실행에서 몇 번째로 실행되는가
const rule = $('출처 검사').last().json;
const model = $input.first().json.output || {};
const fixes = [
  ...rule.failed_rules.map(r => `규칙 위반: ${r}`),
  ...(model.exaggerated ? model.fixes : [])
];
const ok = fixes.length === 0;
return [{ json: {
  retry: !ok && attempt <= LIMIT,
  end_reason: ok ? 'completed' : (attempt > LIMIT ? 'limit_reached' : null),
  attempt, fixes,
  research: $('조사 결과 검사').first().json.research
} }];
```

`$runIndex`는 노드가 한 실행 안에서 몇 번째로 실행되는지를 0부터 센 값이다. 되돌릴 때마다 이 노드가 다시 실행되므로 되돌림 횟수를 따로 저장하지 않아도 된다. 되돌린 뒤에는 `출처 검사`도 다시 실행되므로 `$('출처 검사').last()`로 마지막 결과를 읽는다.

### 7-2. B: 주제별 병렬 조사

`목록 만들기`(3절의 마지막 `Edit Fields`) 뒤를 두 가지로 바꾸어 본다. 두 방법 모두 주제를 규칙으로 나누는 `Code` 노드 `주제별로 나누기`에서 시작한다.

```javascript
// 선택 과제용으로 주제를 미리 정한 목록이다. 실제로는 분류 역할이나 규칙이 정한다.
const map = { 'AI 에이전트': ['P-01', 'P-02', 'P-03', 'P-04'], '개발 도구': ['P-05', 'P-06', 'P-10'], '보안': ['P-07', 'P-08', 'P-09'] };
const posts = $('목록 만들기').first().json.posts;
return Object.entries(map).map(([topic, ids]) => ({ json: { topic, posts: posts.filter(p => ids.includes(p.post_id)) } }));
```

| 방법 | 구성 |
|---|---|
| **갈래와 `Merge`** | `Switch`로 `topic`마다 출력 셋을 만들고, 출력마다 `자료 조사`를 복제한 노드를 둔 뒤 `Merge`(Mode `Append`, Number of Inputs `3`)로 합친다 |
| **아이템과 `Batch Processing`** | 아이템 셋을 `자료 조사` 하나에 넣고 Options → Batch Processing에서 Batch Size `3`을 둔다. 뒤에 `Aggregate`로 결과를 한 아이템으로 모은다 |

두 방법 모두 `자료 조사`의 Prompt를 `{{ '주제: ' + $json.topic + '\n글 목록:\n' + JSON.stringify($json.posts) }}`로 바꾸고, System Message의 3번 줄을 "주어진 주제 하나의 글만 다룬다"로 바꾼다. 합친 뒤에는 `조사 결과 검사`의 입력 모양에 맞게 `topics` 배열을 만드는 `Code`를 하나 둔다.
