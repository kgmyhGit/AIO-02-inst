# 실습 7-5 사내 세미나 준비 도우미 설정

> 실습 7-5에서 쓰는 노드 설정의 완성본이다. 적용 버전은 n8n 2.43.7이다.
> `AI Agent Tool`의 파라미터(Description, Prompt (User Message), Require Specific Output Format, Options)는 공식 문서와 n8n 2.43.7 소스(`nodes-langchain/nodes/agents/Agent/V3/AgentToolV3.node.ts`)로, `Code Tool`의 입력 방식(`query`, Specify Input Schema)은 같은 버전의 소스(`nodes-langchain/nodes/tools/ToolCode/ToolCode.node.ts`)로 확인했다.
> 모든 모델 노드는 `OpenAI Chat Model`(Credential `OpenAI 실습`, Model `gpt-6-luna`)이다. n8n 2.43.7에서 이 설정대로 S-1~S-4와 5단계(반복 한도 `2`)를 이전 실습 모델 `gpt-5.6-luna`로 실행해 3절의 기대 결과를 확인했다. 지금 모델로는 다시 실행하지 않았다.

### 2-3. `AI Agent` — 이름: 준비 감독

| 파라미터 | 값 |
|---|---|
| **Source for Prompt** (**User Message**) | Define below |
| **Prompt** (**User Message**) | `{{ $json.request }}` |
| **Require Specific Output Format** | 켬 |
| **Options → System Message** | 아래 |
| **Options → Max Iterations** | `6`(실습 5단계에서 `2`로 낮춰 보고 되돌린다) |
| **Options → Return Intermediate Steps** | 켬 |
| **Settings → On Error** | Continue (using error output). 두 출력을 모두 `위임 기록`에 연결한다 |

```text
너는 사내 세미나 준비를 돕는 감독이다. 직접 답을 만들지 않고 전문 담당에게 맡긴다.
- find_venue: 날짜, 시간대, 인원으로 빈 회의실을 찾는다.
- estimate_budget: 인원, 다과 수준, 인쇄물 여부로 예산을 계산한다.
- write_notice: 확정된 날짜, 시간대, 회의실, 주제로 사내 안내문 초안을 쓴다.

규칙
1. 요청에 필요한 담당만 부른다. 요청하지 않은 일은 맡기지 않는다.
2. 안내문이 필요하면 find_venue와 estimate_budget의 결과를 받은 뒤에 write_notice를 부르고, 그 결과를 그대로 넘긴다.
3. 각 담당은 한 번씩만 부른다.
4. 오늘은 2026-09-18이다. 날짜에 연도가 없으면 2026년으로 보고, 인쇄물을 말하지 않았으면 인쇄물 없음으로 본다. 빈 회의실이 여럿이면 정원이 인원에 가장 가까운 곳으로 정한다.
5. 날짜, 인원, 주제처럼 담당에게 넘길 값이 요청에 없으면 담당을 부르지 않고 needs_clarification을 true로 두어 되묻는다.
6. 안내문을 직접 보내지 않는다. 보내는 일은 사람의 승인 뒤에 시스템이 한다.
```

출력 스키마(Define using JSON Schema):

```json
{
  "type": "object",
  "properties": {
    "needs_clarification": { "type": "boolean" },
    "question": { "type": ["string", "null"] },
    "summary": { "type": "string" },
    "notice_draft": { "type": ["string", "null"] }
  },
  "required": ["needs_clarification", "question", "summary", "notice_draft"]
}
```

**4번 규칙이 필요한 이유가 있다.** 이 규칙이 없으면 감독이 "연도를 알 수 없다"(S-1), "인쇄물 여부를 모른다"(S-3)며 담당을 부르지 않고 되물었고, S-3에서는 빈 회의실이 둘(대회의실 C, 세미나실 D)이라 장소가 확정되지 않았다며 안내문을 쓰지 않았다(2.43.7, 이전 실습 모델 `gpt-5.6-luna`). 담당에게 넘길 값의 형식(`YYYY-MM-DD`)과 기본값을 감독이 알고 있어야 위임이 이어진다.

`notice_draft`는 안내문 작성 담당이 쓴 초안을 감독이 옮긴 것이다. 옮기며 바뀌었는지는 `위임 기록`이 남기는 중간 단계의 `write_notice` 결과와 비교해 본다(실습 3단계).

세 노드의 공통 설정: Require Specific Output Format 끔, Options → Max Iterations `3`.

| 노드 이름 | Description | Prompt (User Message) |
|---|---|---|
| `find_venue` | `세미나 날짜(YYYY-MM-DD), 시간대(오전 또는 오후), 인원을 받아 빈 회의실을 찾는다. 장소를 묻거나 안내문에 장소가 필요할 때 부른다.` | `{{ $fromAI('venue_request', '날짜(YYYY-MM-DD), 시간대(오전 또는 오후), 인원을 한 문장으로', 'string') }}` |

| 칸 | 값 |
|---|---|
| **Description** | `날짜와 시간대로 예약되지 않은 회의실 목록을 가져온다.` |
| **Resource / Operation** | Row / Get |
| **Data table** | `rooms` |
| **Must Match** | All Conditions |
| **Conditions 1** | Column `date`, Condition Equals, Value `{{ $fromAI('date', '날짜. YYYY-MM-DD', 'string') }}` |
| **Conditions 2** | Column `slot`, Condition Equals, Value `{{ $fromAI('slot', '시간대. 오전 또는 오후', 'string') }}` |

`booked` 조건을 모델에게 맡기지 않는다. 예약된 회의실을 찾을 이유가 없으므로 워크플로우가 고정한다. 정원 비교는 이 실습에서 에이전트가 한다. 정원까지 규칙으로 걸러야 한다면 Data table 조건에 정원 비교를 더하거나 도구를 서브워크플로우로 감싼다.

### 2-6. `Code Tool` — 이름: calc_budget

| 칸 | 값 |
|---|---|
| **Description** | `세미나 예산을 계산한다. attendees(인원, 정수), snack_level(basic, standard, lunch 중 하나), handouts(인쇄물 여부, true 또는 false)를 받는다.` |
| **Language** | JavaScript |
| **Specify Input Schema** | 켬 |
| **Schema Type** | Generate From JSON Example |
| **JSON Example** | `{ "attendees": 20, "snack_level": "basic", "handouts": false }` |

```javascript
// 가상의 사내 단가다. 계산은 모델이 아니라 이 코드가 한다. 결과는 글자 하나로 돌려준다.
const PRICE = { basic: 5000, standard: 9000, lunch: 13000 };
const HANDOUT = 500;
const n = Number(query.attendees);
if (!Number.isInteger(n) || n <= 0) {
  return JSON.stringify({ status: 'invalid_input', reason: 'attendees는 1 이상의 정수여야 한다' });
}
if (!(query.snack_level in PRICE)) {
  return JSON.stringify({ status: 'invalid_input', reason: 'snack_level은 basic, standard, lunch 중 하나여야 한다' });
}
const snack = PRICE[query.snack_level] * n;
const handouts = query.handouts === true ? HANDOUT * n : 0;
return JSON.stringify({ status: 'ok', attendees: n, snack_level: query.snack_level,
  snack_total: snack, handout_total: handouts, total: snack + handouts });
```

`Code Tool`은 에이전트가 넘긴 입력을 `query`로 받고, 글자 하나를 돌려주어야 한다(소스의 안내 문구). 입력 스키마를 켜면 `query`가 객체로 온다.

### 2-7. `Code` — 이름: 위임 기록

Mode는 Run Once for All Items다.

```javascript
// 감독이 어떤 담당을 어떤 입력으로 어떤 순서로 불렀는지 정리한다.
const j = $input.first().json;
const steps = Array.isArray(j.intermediateSteps) ? j.intermediateSteps : [];
const calls = steps.map((s, i) => ({
  order: i + 1,
  tool: s.action ? s.action.tool : null,
  input: s.action ? s.action.toolInput : null,
  result: typeof s.observation === 'string' ? s.observation.slice(0, 300) : s.observation
}));
const failed = j.error !== undefined;
const message = failed ? String((j.error && j.error.message) || j.error) : null;
const out = failed ? {} : (j.output || {});
return [{ json: {
  end_reason: failed ? (message.startsWith('Max iterations') ? 'limit_reached' : 'delegation_failed')
                     : (out.needs_clarification ? 'needs_info' : 'completed'),
  roles: calls.map(c => c.tool),
  calls,
  model_calls_estimate: calls.length + 1,
  summary: out.summary ?? null,
  notice_draft: failed ? null : (out.notice_draft ?? null),
  error: message
} }];
```

`result`는 처음 300자만 남긴다. 추적 기록에 필요한 것은 무엇을 받았는지 알아볼 만큼이며, 긴 결과 전체를 옮기면 기록이 읽기 어려워진다. 감독의 중간 단계에는 감독이 부른 담당(`find_venue` 등)만 담기고, 하위 에이전트 안에서 부른 도구(`find_rooms`, `calc_budget`)는 담기지 않는다(2.43.7에서 확인). 하위 에이전트의 도구 호출은 실행 화면에서 `find_rooms`, `calc_budget` 노드의 실행 기록으로 센다. 반복 한도에 걸린 실행은 오류 출력의 아이템에 중간 단계가 없으므로 `roles`가 빈 배열이 된다. 그때까지 부른 담당은 실행 화면에서 본다.

### 2-8. `If` — 이름: 안내문이 있는가

| 조건 | 값 |
|---|---|
| Boolean — is true | `{{ $json.end_reason === 'completed' && typeof $json.notice_draft === 'string' && $json.notice_draft.trim() !== '' }}` |

```text

■ 요청
{{ $('요청').first().json.request }}
```

## 4. 한 역할을 서브워크플로우로 바꾸어 따로 시험하기(3단계 이후 선택)

`estimate_budget`을 서브워크플로우로 옮겨 따로 시험해 본다.

1. 새 워크플로우 `예산 계산 에이전트`를 만든다. `Execute Sub-workflow Trigger`(필드 `budget_request`, String) → `AI Agent`(Prompt `{{ $json.budget_request }}`, System Message와 도구는 2-4절, 2-6절과 같다)
2. 이 워크플로우만 실행해 "30명, 도시락, 인쇄물 있음"을 넣고 결과를 본다. **감독 없이 역할 하나만 시험할 수 있다.**
3. 준비 감독에서 `estimate_budget`(`AI Agent Tool`)을 떼고, `Call n8n Workflow Tool`(이름 `estimate_budget`, Workflow `예산 계산 에이전트`, `budget_request` ← `$fromAI()`)을 붙인다. Publish한 뒤 S-2를 다시 실행한다.

두 방법의 차이는 이론 표 7-20과 같다.
