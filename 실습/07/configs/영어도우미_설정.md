# 실습 7-2 영어 공부 도우미 설정

> 실습 7-2에서 쓰는 노드 설정의 완성본이다. 적용 버전은 n8n 2.43.7이다. `Text Classifier`의 옵션 이름(When No Clear Match, Allow Multiple Classes To Be True)은 n8n 2.43.7 소스(`nodes-langchain/nodes/chains/TextClassifier/TextClassifier.node.ts`)로 확인했다.
> 모든 모델 노드는 `OpenAI Chat Model`(Credential `OpenAI 실습`, Model `gpt-6-luna`)이다. n8n 2.43.7에서 이 설정대로 라우팅 구성에 시험 문장 12건을 넣어 이전 실습 모델 `gpt-5.6-luna`로 분류와 담당의 도구 선택을 확인했다. 지금 모델로는 다시 실행하지 않았다.

## 1. Data table `vocab`

| 열 이름 | 데이터 타입 |
|---|---|
| `word` | String |
| `meaning` | String |
| `example` | String |

준비 워크플로우 `단어장 채우기`: `Manual Trigger` → `Code`(시험 파일의 `vocab_seed` 배열을 아이템으로 바꾼다) → `Data table`(Row / Insert, `vocab`).

```javascript
// 영어도우미_시험문장.json의 vocab_seed 배열을 여기에 붙여 넣는다.
const words = [ /* 파일의 vocab_seed 배열 */ ];
return words.map(w => ({ json: w }));
```

## 2. 워크플로우 `영어 도우미 단일`(기준선)

| 순서 | 노드 | 이름 | 설정 |
|---|---|---|---|
| 1 | `Chat Trigger` | 채팅 받기 | 기본값 |
| 2 | `AI Agent` | 영어 도우미 | System Message는 아래. Max Iterations `5` |
| 3 | `Data table` 도구 | add_word | 3절 |
| 4 | `Data table` 도구 | find_words | 3절 |

```text
너는 영어 공부를 돕는다. 사용자의 요청은 세 가지 중 하나다.
1. 문장 첨삭: 영어 문장을 고쳐 달라는 요청이다. 고친 문장, 틀린 곳, 이유를 짧게 알려 준다. 도구를 쓰지 않는다.
2. 단어장: 단어를 넣거나 찾아 달라는 요청이다. 뜻을 묻고 외우겠다고 하면 add_word로 넣는다. 단어장을 보여 달라고 하면 find_words를 쓴다.
3. 퀴즈: 단어장의 단어로 퀴즈를 낸다. 반드시 find_words로 단어를 가져와 그 단어로만 낸다. 답은 사용자가 답한 뒤에 알려 준다.
4. 단어를 추가할 때는 find_words를 사용해서 그 단어의 같은 뜻이 이미 저장되었는지 확인하고 없으면 add_word를 사용해서 저장한다.
영어 공부와 상관없는 요청에는 도울 수 없다고 답한다.
```

## 3. 도구 두 개

| 도구 | 설정 |
|---|---|
| `add_word` | Row / Insert, Data table `vocab`. Description `단어장에 단어를 하나 넣는다. 사용자가 외우겠다고 하거나 넣어 달라고 할 때 쓴다.` `word`, `meaning`, `example`은 모델이 채운다 |
| `find_words` | Row / Get, Data table `vocab`, Return All 켬, Conditions 없음. Description `단어장의 단어를 모두 가져온다. 단어장을 보여 줄 때와 퀴즈를 낼 때 쓴다.` |

## 4. 워크플로우 `영어 공부 도우미`(라우팅)

| 순서 | 노드 | 이름 | 연결 | 설정 |
|---|---|---|---|---|
| 1 | `Chat Trigger` | 채팅 받기 | | 기본값 |
| 2 | `Text Classifier` | 요청 분류 | 채팅 받기 뒤 | 아래 |
| 3 | `Basic LLM Chain` | 문장 첨삭 | correction 출력 | 아래 |
| 4 | `AI Agent` | 단어장 담당 | vocabulary 출력 | 도구 `add_word`, `find_words`. Max Iterations `4` |
| 5 | `AI Agent` | 퀴즈 담당 | quiz 출력 | 도구 `find_words`만. 단어장 담당에 붙인 `find_words` 노드를 이 에이전트의 Tool 연결점에도 잇는다. Max Iterations `3` |
| 6 | `Edit Fields` | 되묻기 | Other 출력 | `output` ← 아래 문장 |
| 7 | `Edit Fields` | 답변 정리 | 3, 4, 5 뒤(세 노드를 모두 연결) | `output` ← `{{ $json.output ?? $json.text }}` |

`요청 분류`:

| 파라미터 | 값 |
|---|---|
| **Text to Classify** | `{{ $json.chatInput }}` |
| **Categories** | 아래 표 |
| **Options → When No Clear Match** | `Output on Extra, 'Other' Branch` |
| **Options → Allow Multiple Classes To Be True** | 끔(기본값). 4단계에서 켜 보고 되돌린다 |

| Category | Description |
|---|---|
| `correction` | 영어 문장을 고쳐 달라거나 맞는지 봐 달라는 요청. 이메일 초안처럼 여러 문장이어도 여기에 넣는다. 단어 하나의 뜻만 묻는 것은 vocabulary다. 다른 범주의 요청이 함께 섞여 있으면 여기에 넣지 않는다 |
| `vocabulary` | 단어의 뜻을 묻거나, 단어를 단어장에 넣거나, 단어장을 보여 달라는 요청. 단어의 뜻만 묻는 것도 여기에 넣는다. 다른 범주의 요청이 함께 섞여 있으면 여기에 넣지 않는다 |
| `quiz` | 단어장으로 퀴즈나 시험을 내 달라는 요청. 다른 범주의 요청이 함께 섞여 있으면 여기에 넣지 않는다 |

**Description마다 끝에 "섞여 있으면 여기에 넣지 않는다"를 둔다.** 이 구절이 없으면 E-11처럼 첨삭과 단어장이 섞인 요청이 `correction` 한쪽으로 가고(2.43.7, 이전 실습 모델 `gpt-5.6-luna`에서 세 번 모두), 단어장 요청은 처리되지 않는다. 구절을 두면 E-11이 Other로 가서 되묻는 답이 나온다. 나머지 11건의 분류는 달라지지 않았다.

`되묻기`의 문장: `한 번에 한 가지씩 요청해 주세요. 문장 첨삭, 단어장, 퀴즈를 도와드릴 수 있어요.`

**도구 노드 `find_words`는 하나만 두고 두 담당에 함께 잇는다.** 퀴즈 담당용으로 노드를 복사하면 한 워크플로우에 같은 이름을 둘 수 없어 이름이 `find_words1`이 되고, 모델이 받는 도구 이름도 `find_words1`이 되어 지시문의 이름과 어긋난다.

`문장 첨삭`의 System 메시지는 2절 지시문의 1번 줄만 남긴 것이다. 단어장 담당과 퀴즈 담당의 System Message도 2절에서 자기 줄만 남기고, 퀴즈 담당에는 "find_words 결과가 비어 있으면 단어장에 단어를 먼저 넣어 달라고 답한다"를 더한다.

**담당의 지시문이 짧아진 것을 비교한다.** 단일 구성의 지시문은 모든 규칙을 담아 다섯 줄이고, 라우팅 구성의 담당은 각자 한두 줄이다.

`답변 정리`가 필요한 이유: `Chat Trigger`는 마지막으로 실행된 노드의 `output` 필드를 채팅 창에 보낸다. `Basic LLM Chain`은 결과를 `text` 필드에 내므로 `output`으로 옮겨야 한다. 에이전트는 `output`에 낸다.
